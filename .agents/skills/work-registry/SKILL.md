# Work 开号占号与收尾清理

规则正文在 [Work 登记](../../works/README.md)的编号分配、创建与执行、收尾与清理三节。本 Skill 把最容易出错的两个时点抽成核对清单。

## 开号（三处核对后占号）

1. 先复用符合目标的 Work。确需新编号时核对候选编号无任何引用：`.agents/works/` 已登记目录、本地与远端分支名（`git branch -a` 过滤序号）、linked worktree（`git worktree list`），再以 `git log --all --grep="<workId>"` 兜底。
2. 取已占最大号之后的最小无引用编号；空缺（含只在远端分支存在的号）不回填。与并行执行者明确唯一分配者后，串行完成查号到本地占号：在主工作区创建最小 Work README 与首个可执行 Task 即占号，不要求提交。
3. 撞号时暂停冲突身份的集成，由分配者定保留项，另一项换号并同步目录、`workId`、当前引用与执行路径；已推送内容用后续提交修正，不改写历史。

## 收尾（全部 Task 合入 master 后）

- Work README 记一行固定格式：`已收尾：<master 合入提交号>；待清理：<worktree 路径>、<branch>`；未全部合入时不写，继续用 Task 快照。收尾行引用的提交号在合入提交之后的文档提交里补记。
- `governance:worktree` 报告的 `cleanup: "待清理"` 只是候选来源，不是清理资格：清理前必须核对对应 Work README 的收尾行仍然存在、且该项在收尾行的待清理清单内，收尾行被撤销即失去清理资格。零提交分支（Work 刚占号）也会因「已是 master 祖先」被误标为待清理。删除是受限动作，需开发者授权，删除前逐项确认无未提交改动，清单外一律保留并报告。

## 完成条件

编号三处核对有依据，占号副本与收尾行符合固定格式；清理只动清单内且已授权的项。
