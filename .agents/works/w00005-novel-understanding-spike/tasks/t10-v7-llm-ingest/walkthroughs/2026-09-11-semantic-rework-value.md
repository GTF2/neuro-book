# 有限语义返工的成本与收益抽查

2026-09-11，Tasker cost_scale 只读检查 formal-003/004 已保存候选、C 意见和原文，未运行模型、未恢复 ingest、未修改主线或旧产物。开发者最新目标是正确率、价格、schema 概念数、人类理解和维护成本之间的平衡，不要求 100% 正确。

建议采用“最多一次、只针对有明确原文反证且影响回答的问题”的语义返工；普通补充建议与有争议的分类直接留下可审查缺口。后续研究应按实际查询回答评估，不以 C 全通过或零 missing 作为质量目标。结构非法、精确原文定位失败与语义分歧继续分开处理；本报告没有实施新的发布政策。

## 0 次与 1 次如何选择

**建议默认最多一次，且没有高价值问题时就是 0 次。** 首轮 C 一次性给出少量最影响回答、能指出原文反证的问题；只修这些记录及必要依赖。角色混淆、物品实例错误、思想被别人听到、实际行动与设想混淆优先。摘要覆盖不全、并非必需的分类实体、媒介没有明说、可从已有材料找回的次要细节，保留意见和原文入口，不触发整章返工。

返工后保留稳定的未变记录，校验修改项及受影响依赖；新增发现进入已有运行审计与覆盖说明，默认不再触发第二轮语义重做。已指出错误仍无法合理修复时，查询时应看到相关内容有争议或尚不完整，不能为了发布把 C 强行改成 passed。本报告建议调整发布合同，尚未实现这种行为。

实现这个权衡不需要扩充 V7 领域 schema。复用现有来源归属、tentative/评估、coverage 和运行审计；不新增 QualityIssue、RepairPlan、ReviewSession 等图节点，不再按每个审查意见增加一层人类要理解的状态。人类只需知道“这段回答的依据是什么、哪一点还不确定”。审计中的章号、记录 ID、原文段号和简短说明足够回查。

“风信子是不是前章目标”这种暂定同指，以及“听到还是读到通讯”这种媒介不明，是现有概念使用是否合适的问题，不能只靠增加更多类别解决。未来是否简化这些概念应由新的 20 章查询体验决定；本轮不改 schema。

完成新的 20 章后，应由独立查询 Agent 用既定问题检查正确回答、错误回答、缺答案、需要回原文的次数以及模型费用。这个结果才能支持成品的价格/正确率选择；当前有限样本仅支持停止无上限语义返工、优先局部修正的方向。
