## 已确定的取舍

- 复用 t07 领域合同、t09 查询；原文按 V7 body-blocks-v1 提取。V6 第 1 章是 77 段、V7 是 76 段，不能直接复用 V6 的段号或其抽取结果。
- 三阶段模型调用：A 只读当前章提取材料，B 增量整合，C 独立语义复核。B/C 读取当前章及选中的已发布知识和原文依据，不输入手工金标。
- 使用紧凑且严格的 JSON 候选，模型不输出完整的重复引用封套。程序编译稳定 ID、精确 UTF-16 Span 和依赖结构，语义来自模型候选与复核，最终统一通过 t07 校验。
- B 确定完整语义论元后可以显式补充 A 遗漏的局部指称及精确原文提及，只新增，不改写 A。合并材料统一校验 ID、原文和时间，并全部交 C 复核；补充不能掩盖原材料的错误归属。
- B 在调用 C 前完成确定性候选编译，失败时保留 A，仅向 B 反馈上一候选和精确错误。length 截断增加输出容量后有限重试；反馈、上一候选和容量变化在恢复前后保持一致，避免拒绝已付费响应。
- JSON 文件承载请求/响应、不可变阶段产物、每章快照和原子 head。独立 SQLite 协调文件持有运行排他锁，利用 OS 崩溃释放；不把业务数据迁入数据库，不预建生产调度器。第一版 PID 锁文件自动接管经双进程审查发现竞态，改用数据库文件锁解决，不叠加手写恢复锁。
- Entity 名称追加存在互相引用版本问题，采用每章完整快照重新赋版本。旧 snapshot 不可变，所有新节点/RecordRef 版本一致；承担 20 章范围的完整重编译成本。未来细粒度存储另行设计。
- 摘要仍遵守 t07 builtFrom 严格新鲜度。新章生成新摘要记录，保留旧记录；用旧章快照读取历史摘要。不得改旧 builtFrom 或将摘要当新证据。
- 查询质量由 20 章结果后的真实 Agent 评价；本轮仍独立检查代表性事实、原文和范围，不能只以 schema 通过宣称质量合格。

## 边界检查

每一阶段先通过有限验证再扩大。20 章运行前必须有实际 API 返回和至少一个完整章节的查询证据；如果接口或模型行为不符合预期，保留失败并修复，不在未验证管线上消耗整个运行。不限量授权保持有效，有限重试只是自动故障恢复边界。

使用已有 Bun/Node、TypeScript、Zod、fflate 和结构化 XML/DOM 工具。Ingest CLI 使用 Node 24.13+ 和 `node --import tsx cli.ts`，利用 `node:sqlite` 持锁；Bun 可调用 package scripts，不把 `bun cli.ts` 当作已验证的 ingest 入口。测试、fixture、短时 smoke 路径遵守测试支持包；需保留的实际模型开发实验作为研究 evidence 登记。只提交明确范围文件，不包含历史 V6 修改、缓存或凭据；远端写入未授权。

## 成本设计

开发者澄清：开发无限 token，不要求节省开发成本；2026-09-11 明确评估对象是单本一千万字的长篇。费用按官方峰谷价和实际 input/output/cache-hit/cache-miss 计量，缓存和未知结果不得按免费处理。生产有效调用、正常重试率与开发策略试验分开统计，不加入人为开发预算或审批中断。成品规模估算同时给出字/token 比、输入重复倍数、输出密度、候选上限和复核比例，不能仅线性乘以一章且忽略后续上下文膨胀。

当前选择：A 只读章内原文，B 检索前缀中的有界主体/谓词候选及相关知识，C 使用候选和其依据；稳定系统/输出合同放在可缓存前缀，候选用紧凑 JSON。上下文按相关事实及直接依据成组选择，预算不足整组跳过，缺项可见；当前没有单独把前章尾全文交给 A。仅对活跃变化的主体做模型摘要更新，未变化摘要通过本地依赖检查复用。语义仍逐章增量，整快照重编译由本地程序执行，不为同一导出重新调用全书模型。每次恢复优先消费已保存响应。重复文本命中缓存只是费用机会，不假设供应商一定命中。产品成本模型与生产存储边界见 [规模与成本设计](scale-and-cost.md)。
