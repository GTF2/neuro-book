# 按记录修复的成本实验

formal-003第4章多次发生少量结构纠错后又引入别处错误，且每次仍输出完整A/B候选。本实验只回答：同一修复输入下，只返回相关记录的替换，能否减少输出和对无关内容的改动，同时通过既有确定性校验。

使用4份已保存的真实修复请求：第1轮A attempt-2（非法mode）、第2轮B attempt-4（身份ID拼写）、第5轮B attempt-4（相遇双方角色重名）、第1轮B attempt-2（可用时间）。保持deepseek-flash、thinking enabled、原文、旧上下文、原候选和错误反馈；更换输出合同为按集合与id定位的完整记录替换，容量沿用原请求。真实API和token已获开发者授权。

补丁只可替换已有记录，不能新增、删除、重命名、修改原文或改写旧审计。重复目标、不存在的ID、歧义基底、非法集合/记录全部拒绝。合成候选必须经过原material/integration schema、原文范围/提及、known引用和完整快照编译；未替换记录内容必须逐条保持不变。补丁通过仅说明结构有效，不代表语义正确；不发布、不改变主线修复策略。

步骤：先实现独立补丁应用与边界测试；随后保存4次模型请求和响应，复用已保存响应时不再调用，未知结果不重发；最后与各自原请求的输出用量、成本和校验结果比较。该单次修复对照不覆盖语义返工、增删记录、端到端收敛或20章质量。结果无论正负都保留，不能把低价失败样本当作成品单位成本。

实验已完成，原始脚本、补丁实现及测试保存在 `../../evidences/record-patch-001/experiment-source.json`。之后将补丁实现与测试移到 Task 根目录作为唯一运行期模块，本实验脚本复用 `../../record-patch.ts`；请求/响应保持原样。策略 -4 的完整恢复合同另由 Spec 与 runner 测试验证。
