# 查询收益评测

本目录只保存研究工具，不进入ingest运行依赖。评测问题和参考答案由编号原文生成，再由独立请求核对；不读取金标、ingest候选或查询指南。它们是待原文抽查的模型辅助评价材料，不宣称人工金标。样本在运行基线和精简方案之前冻结。

前6章准备40题（普通查询与易混淆边界分组），7..20章另备40题。参考答案与证据不进入查询作答模型或ingest模型；查询作答仅获得问题、阅读上限及统一工具合同。评分时再使用原文依据。原文无法给出确定答案的问题允许回答无法判定。

prepare.ts通过--split development或holdout创建样本；--epub指定原文，--root指定持久研究证据目录，--env-key指定密钥环境变量名。请求、响应先保存再校验，重复执行优先复用已保存响应。准备与独立核验各一次；核验有实质问题时输出修订后的完整题目，原始样本不覆盖。准备和核验成本属于开发评测，不能计入成品ingest单位价格。

样本记录问题、readAt、类别、参考回答和逐字原文引用。程序检查引用真实存在、没有越过阅读上限、ID唯一及章节覆盖；语义判断仍需独立原文抽查。最终报告分别呈现普通问题与边界问题，以及前6章调试样本与后14章验证样本。

evaluate.ts接受--suite、--data-root、--root、--mode graph/graph-source/source、--env-key和--concurrency 1..8。按题目readAt选择对应章快照，使用同一t09查询服务；每题最多6次查询、每次10项、最多4次模型行动和100000字符工具结果。查询模型thinking disabled，独立评分thinking enabled，这些是固定评测条件，不改变ingest思考策略。graph允许记录自带原文摘录，graph-source另允许source命令，source只允许原文命令。三个模式独立作答，不能把允许原文模式的成绩解释为图直接检索成绩。

作答模型仅获得问题/阅读位置和实际工具结果，不获得参考回答或证据清单；答案先不可变保存，再单独评分。参考答案和评分都是模型辅助判断，报告需要独立原文抽查，并保留完整失败分母。查询范围不能由模型扩大，非法请求消耗同样的工具预算。请求已有记录但没有响应时保持未知结果，不静默重发或计零。

原文参照必须使用同一真实章快照并禁止图查询。source-reference.ts曾试验空图容器，但t09从可见图记录识别world，空图的source命令不可用；query-source-evaluation-001因此已排除质量比较，费用保留为开发试验。该脚本和原产物仅保留失败复现，不作为有效参照。当前evaluate.ts在付费调用前先检查每题的原文入口，避免把工具不可用误报为知识漏答。

## 评测合同修正

第一轮在1..5章各模式运行32题，源码身份943c4ded52848c5d320e96eb242f73dd35da2dcc1a3c1d2dcce1f03edd5520d5，源码保存于../../evidences/query-evaluation-contract-v1.json。执行层限制每页10条，但完整CLI schema默认20条，且向所有模式展示了被禁用的命令；已有调用因此花掉预算。这是评测适配器缺陷，不能算作ingest漏抽证据。

修订只统一研究合同：向模型给出的action schema仅列当前模式允许的命令，分页最大值与默认值都为10；执行端省略limit时也使用研究默认10，显式超额仍拒绝。公共t09 CLI默认20不变。scope、问题、答案、查询模型、思考模式、6次工具预算、4次模型行动和评分请求全部不变，新增一致性回归通过。新运行目录含v2，逐次保存evaluation-source.json；两种源码身份分别报告，不拼成同一个成绩。

v1原始结果保留作诊断及开发费用；v2对同一冻结40题的三个模式配对重测一次，后14章同样使用v2。明确允许原文只代表工具可用，不保证查询模型一定选对检索词或证据。评分模型也可能误判：v1 graph/q07已引用包含任务、目标与奖励的三条Fact，评分仍因只列一段原文而判部分证据。最终成绩应附原文抽查与评分争议，不能把自动评分当作人工金标。
