# 成品长篇规模与成本

开发者要求成品 ingest 价格可接受，并明确开发/调试无限 token；2026-09-11 进一步确认“千万级别的书”指单本一千万字的长篇。本设计评估单本模型工作量、上下文与摘要更新随原文增长的成本。20 章实验用来测模型输出和单位用量，不能独自证明千万字质量或运行性能。

## 控制增长的边界

| 环节 | 成品设计 | 避免的增长 |
| --- | --- | --- |
| 原文提取 | 当前章或完整局部片段，必要前文显式登记 | 每章重发整本原文 |
| 身份候选 | 名称/局部描述/近期事件检索，限定候选和证据预算；无匹配保持新对象/未定，必要时继续检索 | 把所有历史实体及摘要放进每次提示词 |
| 增量整理 | 仅处理本批涉及的对象、关系族和事件，有依据地连接已有过程 | 每章重新归纳全部知识 |
| 摘要 | 只重新生成受影响 facet；未变条目本地验证依赖后复用；限制摘要大小并支持分层索引 | 全部人物摘要随每一章重新调用 |
| 语义复核 | 覆盖新建/改变的语义单元及其必要原文；重复发布不再付费 | 每章重新复核全书所有旧记录 |
| 持久化 | 生产保存不可变增量版本、邻接和倒排索引；快照逻辑化 | 每章永久复制完整全书状态 |
| 跨章重整 | 有触发条件/范围的增量任务，周期整理单独计量 | 无变化仍反复全书“思考” |

本轮 t07 兼容导出仍重新编译完整快照，因此本地 CPU/磁盘累计成本可能为平方级；这是明确的实验折中，不能作为成品存储设计。模型调用必须已经按章节和活跃变化组织，不能把实验规模的小掩盖全历史提示词增长。

有界上下文也必须验证内容分配。初始实现先展开全部主体身份链，48 主体的本地测试就使事实、情节、摘要和知情全部被挤出；已调整为主体目录与四类语义种子先保留空间，再补相关依据。上下文包括封套在内限 90k 字符、最多 150 条记录，缺失引用和各类裁剪显式计数。长篇未知别名的召回仍需后续索引验证，不能以有界长度宣称身份连续性已解决。

## 测算方法

每章记录原文 Unicode 字符数、各阶段 input/output/cache tokens、响应 model、时段和失败类型。生产基线分别呈现已接受运行的必需 A/B/C 与正常修复尝试；开发方案变更、格式试验和手工诊断另计。

设单本正文字符数为 C，每百万字实际生产输入和输出为 I、O，则先以 C/1,000,000 乘单位用量，再按输入命中/未命中及输出价格计算。该线性外推仅在检索上下文和摘要范围有界时成立。报告同时给出后几章相对前几章的上下文增长，缓存全部未命中、实测命中、高峰价格、输出/修复倍增等情景，不能只给最乐观一个价格。

后续更新以新增/修改正文及实际受影响的知识量计量，不每次重跑全书。内容哈希、原文版本与策略身份相同的重复任务复用已发布结果；模型升级导致的重建另列覆盖范围与费用，不能隐藏在首轮单价中。总拥有成本还包含存储、索引、调度/带宽及质量复查，本轮 API 测量不包含这些费用。

当前官方 Flash 每百万 token 低峰：输入未命中 $0.15、命中 $0.003、输出 $0.6；高峰分别 $0.3、$0.006、$1.2。价格和来源见 [API 核验](deepseek-api.md)，不是供应商账单保证。

报告额外区分供应商明确返回的推理 token 与非推理输出；未提供分项时标记未知。开发 smoke-002 中，三次被截断的 C 调用共 72,000 个输出 token，其中 58,731 个为推理，占 81.57%。这不能用作生产单位成本，但说明最终优化需要比较审查粒度、思考策略及语义质量，仅压缩 JSON 封套未必改变主要开销。输出上限只是容量，不是实际消费预算；足够容量可避免必然截断后的重复付费。

报告的 `contextGrowth` 是实际输入 token/原文字数的前后章比值，包含重复尝试和候选大小的影响；判断检索上下文本身是否增长需同时读取逐章 `context.characters`。`peakNoCacheDoubleWork` 表示全部模型工作量翻倍，不能描述成只让修复次数翻倍。2026-09-11 独立成本复核通过 cost/report 11 项测试与类型检查；尚无完整 20 章单位成本结论。

例如仅作公式示范：假设千万字产生 100M 未命中输入 tokens 和 20M 输出 tokens，低峰约 $27，高峰约 $54。这个数字不是本管线的实测预测；最终用 20 章的真实用量替换假设，并披露超长篇新增对象、长距离身份召回和重新整理可能增加费用。

## 待本轮填入的证据

已做 [9 次真实思考模式对照](walkthroughs/2026-09-11-thinking-cost.md)：六个主样本的输出 token 减少80.12%，统一无缓存低峰估价下降66.47%，但两次整合未通过确定性校验，复核出现已知错误的漏判及与当前候选不符的理由。因此未将主线切为非思考模式，不能把低价失败调用外推为成品成本。当前优化先减少已通过材料的重复处理，并让复核只评估当前候选。

- 正式 20 章有效生产各阶段 token/费用与每百万字用量。
- 原文总字数、输出记录密度、前后章提示词大小和复核占比。
- 千万字的实测基线、高峰/低缓存/高输出/修复情景。
- 召回有界导致的质量风险、尚未实测的千万字索引与存储能力。
