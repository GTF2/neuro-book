# V7 ingest 的质量、价格与复杂度取舍

2026-09-11方向修订。开发者要求先暂停、分析和计划，再继续。本文区分已实现基线、已有证据和待比较方案；不把后者当成已生效合同。t07 schema、EntitySummary和t08保持只读。当前行为见 [Spec](../../../../../docs/specs/memory/v7-llm-ingest.md)，执行顺序见 [计划](plan.md)。

## 目标修正

成品的价值是让Agent用合理费用找到长篇中的人物、关系、情节、知情与原文依据。图是可追溯的检索和组织工具，不要求把整本小说转为穷尽、无歧义的形式系统。允许漏掉次要细节、保留不确定解释和回查原文；不能把这些情况包装成确定结论。全文材料完整保存，语义提取明确为partial。

评价单位优先是“某个问题在给定阅读位置能否得到有依据的回答”。正确率、召回、费用和维护复杂度分开报告，不用节点数、C通过率或一个人为加权总分代替产品效果。开发token无限不等于可以把人工诊断和无限返工当作成品运行方式。

上一轮只限制语义返工次数，仍默认每章A材料、B整合、C逐项复核全部必要。这个前提尚无比较证据；已有实现投入也不能成为保留全部步骤的理由。

## 现有证据的含义

- [12个主题的原文核查](walkthroughs/2026-09-11-semantic-rework-value.md)既发现值得修复的思想/发言混淆、人物归属及物品实例合并，也发现复核误读和整章重写丢失已修好的内容。更多轮次不保证更好。
- 三个多轮样本截断到首轮加一次返工，旧账目分别少42.82%、58.31%、43.39%。这只支持限制循环，不是新流程的节省率或正确率。
- [关闭思考的阶段对照](walkthroughs/2026-09-11-thinking-cost.md)中输出明显减少，但有结构失败与语义漏判。它不能证明复杂提示词直接关闭思考可以满足产品需要，也不能证明所有较便宜流程都不可用。
- smoke-007首章277条最终记录、172个复核单元，其中包含来源和支持记录，不能当作277条用户知识，也不能仅凭数量断言过度建模。应检查每类记录实际服务了什么查询。
- 策略-5有限发布已通过80项测试、类型检查和独立恢复复核；真实smoke-008在首轮C等待响应时依用户指令停止，head=0，尚无该策略完整章节或20章质量证据。

## 默认建模范围应更小

| 保留的能力 | 查询收益 | 默认不额外展开 |
| --- | --- | --- |
| 主要人物、关键物品和跨章身份 | 连接同一对象，避免同名或同类物品误合并 | 每个普通名词、修辞和一次性背景对象 |
| 持久属性、目标、规则与关系变化 | 人物档案、世界设定和关系查询 | 每句话、短暂动作和重复转述的独立Fact |
| 关键事件与过程 | 发生了什么、前因后果和跨章延续 | 没有查询收益的多层事件树或因果推演 |
| 关键披露与明确获知 | 谁说了什么、谁听到，以及世界是否为真 | 根据提到、在场或常识推导所有人的完整信念状态 |
| 原文依据与现有摘要 | 核查、补查和快速阅读 | 重复复制依据、长篇复核评语、摘要作为新证据 |

这是抽取粒度选择，不是新增另一套schema，也不是把所有东西改成Entity。仍保留“谁说的”和“世界事实”的区别；“未知”不能写成明确“不知道”。对象实例、否定与关键限定如果会改变回答，就不能为压缩而删掉。模型负责语义选择，程序只生成可确定的ID、引用封套和版本，不代替模型猜身份、因果或时间。

例如“苏天晴知道造物主吗”：需要关键披露、苏天晴的明确获知及原文，才能说明截至哪一段、她获知了什么。仅有两个实体或文本共现不足以证明知道；遗漏该获知时应报告未找到记录并回查原文，不能回答“不知道”。这种直接影响查询的内容优先于大量短暂动作。

## 流程选择仍需实验

先比较现有三阶段基线与减少默认建模的三阶段候选，确定省下的工作是否损害关键查询。之后仅在仍有明确的A/B重复开销时，比较一次联合提取与整合，再保留一次独立C。合并可能增加单次难度和结构修复，不能根据调用次数就断言省钱。最终只维护获选流程，不建设多策略调度平台。

逐项C也不是永远不可改变的产品原则，但暂不直接删除。当前编译器把C判定写入Argument，查询据此产生Assessment和身份/摘要可用性。跳过C会影响这些行为，不能给没审过的内容伪造passed。首轮合并实验继续审查全部保留候选；按风险抽查、按需复核或取消独立复核属于有证据再讨论的合同变化，本轮不同时实现。

复用现有最多一次语义返工边界。优先修有具体原文依据且会改变回答的问题；措辞偏好、非穷尽细节和建模口味不应触发整章重做。剩余拒绝在基线中按现有pending及依赖投影处理，问题完整保存。必须测量隔离丢失了多少可回答内容，不能把错误藏起来就算质量提升。已有结构补丁不代表语义局部修复已经实现。

结构、原文坐标、引用、时间/依赖和恢复是可确定的程序合同；保持严格不等于承诺模型语义100%正确。程序不能检查出的语义错漏进入查询评价，不逐例增加特殊规则或领域节点。

## 评价与选择

先独立从原文固定问题、阅读位置和证据段落，普通查询与已知高影响反例分组统计。问题与答案不进入ingest输入。各方案使用相同问题、查询模型、工具预算和评分口径；先测图内可回答性，再单列允许原文补查后的结果与追加成本。

记录正确且有依据、部分回答、错误、未找到、原文不足以判定，以及引用是否真正支持答案。原文不支持确定结论时，明确无法判定是合理回答。单列人物/物品误合并、角色知情混淆、否定丢失和未来信息泄漏；报告分母与例子，不从小样本宣称整书准确率。

成本按全部正常调用及修复计算，另列人工诊断次数；复杂度记录新增概念、模型必填语义字段和特殊处理分支。先排除各方面都更差的方案。更贵、更复杂的步骤若没有稳定改善同一组关键查询，就不保留。若存在真实权衡，列出多花多少钱、改善哪些问题、仍漏什么；收益接近时优先简单方案，不冒称全局最优。边缘结果最多一次预先限定的复测或通用修订，避免不断修到满意。

不预定95%或99%正确率，不默认每章固定事实数量，不为每类错误增加节点和状态。千万字估价包括正常修复和查询补查情景；长程召回与增量存储仍未验证，20章只能为方向选择提供证据。
