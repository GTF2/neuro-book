# 前两章金标：标注范围与语义复核

## 来源与标注立场

开发者于 2026-09-09 要求用实际 EPUB 前两章制作金标、用通用 V7 查看器展示，并允许按实际抽取情况调整模型。

`sources.json` 保存 EPUB 和各 XHTML member 的哈希、OPF 路径、选择范围及归一化正文。使用 XML 解析器读取 body 直接块，排除 head/title，保留正文 h1、作者声明和分隔行。第一章 76 段、第二章 87 段。旧 V6 包含 head/title 的规范化产生不同坐标，不能直接套用旧段号。

`annotations.json` 是 Agent 逐段阅读后编写的语义标注，`dataset-v7.json` 是确定性编译产物。编译器分配具体记录和引用，不生成新的小说语义。本次“金标”指待开发者审阅的参考答案集，尚未获得人类认可，也不能用编译通过来证明语义全对。

Beat 覆盖全部 163 段；重要命题、关系、认知、事件和歧义逐条标注。拟声、过渡、纯修辞和重复情绪保留在原文及 Beat 内，不强行为每句建立 Fact。例如第一章的太奶幻象留在前世回忆材料中，不确认其实际出现。

## 独立语义审查

独立 Agent 在隔离上下文中通读规范化两章与标注，只报告反例。发现的四项均有具体原文依据，裁决为有效并修正：

1. `d107/f107` 原范围漏掉第一章 19 段的“你干嘛呢”，并把叙述者对古书不解的说明混成发言。扩到 19–21 段，Fact 独立只记录实际发言内容；披露仍保留叙述说明。
2. `d209` 把第二章 21 段角色所想的“死法一模一样”改弱成“类似”。原主病史保留在 `f209`，另以 `d229/f229` 忠实记录角色等同判断。两种疾病不能因此在世界层合并。
3. `body` 名称“金毛狐女”在第一章 10 段才出现。实体入口和正式名称边界改为 10 段，外貌披露仍覆盖 8–11 段并在完整范围后可用。通用编译器也必须按名称自身位置判断可见性。
4. `d118` 混合公开提问与内心担忧，`d225` 混合翻书行动与页面显示。新增 `d130` 保存提问、`d230/f230` 保存行动；原记录分别限定在内心担忧和页面内容。schema 允许 Fact 文本独立于披露概述。

第二轮独立复核确认上面四项修复符合原文，并对新增时间和认知标注提出四项问题，均已采纳：

1. `f105` 的“正在回忆”与被回忆的前世倒下时间混用；去掉错误 Fact.time，使用披露 mentionedTime 和命题 recalledTime 表示内容中的过去。
2. `f208` 完整命题混入晚于录取的患病，现独立命题只保留考上医学院；病情仍由 `f209` 表达。
3. `mirror` 早期叫落地镜，“卧室落地镜”的完整显示名延至第二章 69 段，与房间名称边界一致。
4. `f225/f226/f227` 来自角色看到书页，认知访问模式新增 `read`，与 `heard` 分开。

修正后的结构和查询验证另见本 Task 验证记录。本次没有调用外部 Provider 做自动抽取，也没有运行外部 CLI 跨模型复核；独立 Agent 审查不代替开发者认可。

## 审查重点

十二条 `cases` 保存预期查询入口与禁止提前出现的引用。它们覆盖契约、受助者身份、操作过程、角色未知、奖励条件、同名拆分、疑问语气、没有回应、剧情组织、名称提前、组织集合和态度变化。

这些是两章范围内的验收依据，不能证明自动抽取召回率、整书性能、任意自然语言逻辑推断、持续梦境、数据库事务恢复或全书集合穷尽。后续自动抽取应与经开发者修订的标注比较，并将缺项与错误推断分别报告。
