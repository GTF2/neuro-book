# 稿面评审：真实浏览器实测版

> 日期：2026-09-17 · 状态：`review`（基于真实渲染，非代码推断）
> 评审对象：NeuroBook 工作台 · 打开一章正文后的真实界面

---

## 0. 为什么重做这次评审

前几轮我对界面的判断都建立在**空状态截图**（欢迎页）上。那评的是首页，不是主场景。

**主场景是「打开一章、正在写」的那一屏。** 这份评审只评那一屏。

方法：Playwright + 本机已下载的 Chromium，驱动真实浏览器进入工作台、展开文件树、打开 `manuscript/000-opening/index.md`，然后截图 + 量测 `getComputedStyle` 的实际值。

---

## 1. 结论先行

**病灶不是「元素多」，是「元素之间没有层级」。**

打开一章后，屏幕上同时存在四个平级的面板区，每一个都有自己的 header 和按钮排：

```
活动栏(48) │ 文件树(~420) │ 稿面 │ Agent 面板(~390)
                              ↑ 主角，但看上去和邻居一样重
```

量测证据：

| 指标 | Agent 面板关闭 | Agent 面板打开 |
|---|---|---|
| 屏幕上可见按钮数 | **18** | **37** |
| 稿面宽度 | 908px | 724px |
| 正文行宽 | 860px | 676px |

**打开 Agent 面板这一个动作，把屏幕上的可点对象翻了一倍。** 而稿面在视觉上并没有因此变得更"重"或更"亮"——它只是变窄了。

## 2. 逐条发现

### F1 · 标题在同一屏出现 4 次（可数）

量测：文本 `开篇：蓝梓与芥末` 在一次渲染里有 **4 处可见**：

| 位置 | 出现形式 | 坐标 |
|---|---|---|
| 顶部标签 | `开篇：蓝梓与芥末` | y=11 |
| 正文 H1 | 章标题 | y=144 |
| 左栏文件树行 | 树节点 | y=261 |
| 左栏详情面板 | `标题 / 开篇：蓝梓与芥末` | y=693 |

四处各有理由（标签是"当前打开"，树是"在哪个位置"，H1 是"文档内容"，详情是"这一章的身份"），**合起来是同一句话说了四遍**。眼睛在四个地方读到同样的信息，就学不会"哪里该看"。

→ 建议（未实施）：树行与详情面板去重；顶部标签在只有单标签时不必显示文件名（正文 H1 已经说了）。

### F2 · 稿面第一眼是元数据，不是正文（已修）

打开一章，正文上方第一眼是一张**带描边、带底色**的卡片，内容是一行等宽字体的 YAML：

```
> title: 开篇：蓝梓与芥末        [✎] [🗑]
```

右侧还常驻一个**红色垃圾桶**（删除 frontmatter），随时待命。

这是写作工具里最"工程感"的一处：读者打开一章想看故事，先看到的是一条 YAML 和一个删除按钮。

→ **已修**（提交 `35a0890d`）：折叠态平时不描边不填底、摘要行降到 `--text-muted`、操作区（含删除）平时透明且不可点，hover / focus-within 才浮出。见 `C1-frontmatter-quiet.png` 与 `C2-frontmatter-hover.png`。

### F3 · 专注模式的初始判定是错的（已修）

这是我上一轮交付的功能，在真实界面里第一眼就是坏的：

**开启后，标题独立保持全色，正文 131 个块全部降到 28% 不透明度。** 观感是"文字被禁用了"，而不是"专注模式开着"——比不开还糟。见 `A2-light-focus.png`（修复前）。

根因：ProseMirror 打开文档时默认把选区放在文档起点（也就是章标题里），标题是 textblock，于是被判定为"当前块"。

→ **已修**（提交 `337b8493`）：标题排除在"当前块"之外，顺延到它后面第一个正文块。修复后 `B1-light-focus-fixed.png`：标题作为结构退后，正文第一段被点亮。点正文中段，高亮正确跟随（`B2-light-focus-mid.png`）。

> 这条证明了本文件夹存在的必要性：**读代码完全看不出问题，静态截图也看不出**。只有让它在真实浏览器里跑起来、点一下工具栏按钮，才会看到"整篇变灰"。

### F4 · 工具栏 6 个入口全是纯图标

稿面顶部一排：分段控件（富文本/源码）、准星（专注写作）、对话气泡（评论视图）、魔法棒（扫 AI 味）、更多。**没有一个有文字标签。**

`title` 属性只在 hover 时出现——**鼠标悬停不算视觉引导**，它是隐藏式帮助。用户要在 6 个抽象图标里猜哪个是"专注写作"。

→ 建议（未实施）：把"扫 AI 味""评论视图"这类低频项收进"更多"，常驻只留当前视图切换 + 专注写作；或给常驻项加文字短标签（空间足够：这一排目前只占约 180px）。

### F5 · Agent 面板的空态是死路，不是发射台

打开 Agent 面板，中间是：

> 请选择一个对话
> 当前实例还有可用对话，但没有可用的上次选择。请从对话列表中选择。

**两行说明文字，没有一个可点的动作。** 用户被告知"请从对话列表中选择"，但对话列表在哪、怎么进，没有指示。

→ 建议（未实施）：空态给三个可点起点（新建对话 / 从模板开始 / 查看已有会话），并把"选一个对话"这件事变成一个动作而不是一句说明。这是 `SIMPLIFICATION.md` 里 G6「空态即演示」在 Agent 面板上的具体化。

### F6 · 主题：`light` 不是为写作工具设计的

`A1-light-default.png`（当前使用）与 `A3-sepia-default.png` 对比，观感差距不需要解释：

- `light` 是**纯白 + Tailwind 默认灰阶**（`--bg-panel #ffffff`、`--border-color #e5e7eb`、`--text-main #111827`）——一套框架默认值，不是设计决策
- `sepia` 是暖纸底 + 赭石橙（`#fdf6e3` / `#d97743`），跟正文的"纸"这一形态同源

而这个产品**原本的默认主题就是 `sepia`**（`resolve-theme.ts` 的 `DEFAULT_THEME_ID`）。现在窗口用的是 `light`。

→ 建议（未实施，零成本）：改回 `sepia`。暗色场景推荐 `tokyo-night`（最克制的蓝灰）。8 套对比见 `themes/00-overview.png`。

### F7 · 左栏详情面板（**经查证不是问题**）

初看像是"左栏被切成两半，下半是只读的统计与元数据"，很冗。

查证后撤回：`WorkspaceFileDetailPanel` **可关闭（`×`）也可拖拽调高**（`:height` / `@update:height`），是上下文相关的面板，不是强制常驻的 chrome。

## 3. 本轮落地的改动

| 提交 | 内容 | 验证方式 |
|---|---|---|
| `337b8493` | 专注模式：光标在标题上时不再把整篇正文变灰 | 浏览器实测（A2 修复前 → B1 修复后）+ 3 条新断言 |
| `35a0890d` | frontmatter 卡片在写作面上退成配角 | 浏览器实测（平时 transparent / hover 浮出） |
| `aa424195` | 简洁档让导航 chrome 退场，稿面成为唯一亮面 | 浏览器实测两档位下五个区域的实际绘制底色 |

第三条补齐了本评审 §1 的结论——它把"没有层级"变成了可测量的层次：

| 区域 | 标准档 | 简洁档（sepia） |
|---|---|---|
| 活动栏 | `#f0f2f5` | `rgb(235,224,200)` |
| 左侧工具面板 | `#ffffff` ← 与稿面同值 | `rgb(244,236,216)` |
| 稿面 | `#ffffff` | `rgb(251,245,231)` ← 最亮 |

**标准档下工具面板与稿面底色完全同值**，这是"分不出主次"在像素上的样子。简洁档给出了三级明度，眼睛有了可循的方向。见 `D1-full-editor.png` / `D2-quiet-editor.png` / `D3-sepia-quiet.png`。

## 4. 下一步建议（按影响面排序）

**① 让稿面成为唯一的高对比区域** —— **机制已落地（`aa424195`），但要扩大覆盖面**

手段已经能用了：角色映射层的 `--panel-surface` 有了第一个消费方（左栏工具面板），简洁档一开就能让导航 chrome 退场。

剩下的是覆盖面：还有若干面板外壳仍直接消费 `--bg-panel`（`PlotThreadPanelShell`、`NovelRagInspectorSidebar`、`PlotWorkbenchSidebar` 等）。做法是逐处 `bg-[var(--bg-panel)]` → `bg-[var(--panel-surface)]`，**每处观感零变化**，但都能被档位统一控制。

判断标准：**它是不是"让你走到某处"的面板？** 是就换。"让你读/写"的面板（稿面、Agent 对话）不换。

**② Agent 面板空态给可点起点**（F5）

成本低（一个组件 + 词条），收益直接——它是用户"打开 Agent 后不知道干什么"的全部原因。

**③ 标题去重**（F1）

成本中（牵动树行、详情面板、顶部标签三处），需要产品判断。**建议放在①之后**——层级建立起来之后，"哪里该显示标题"会自然有答案；现在做等于拍脑袋。

**④ 稿面工具栏收噪音**（F4）

成本低，但优先级低于①：图标不可发现是"找不到功能"，而①解决的是"没有重心"——后者才是用户原话里的问题。

- 量测取的是 `getComputedStyle` 的即时值，未做跨主题全量遍历（除 F6 引用的 8 套对比图）。
- 本轮**没有跑主应用全量测试**（259 个组件测试），只跑了与改动直接相关的：专注模式 28 条、主题目录 38 条。
