## 1. 结论先行

**病灶不是「元素多」，是「元素之间没有层级」。**

打开一章后，屏幕上同时存在四个平级的面板区，每一个都有自己的 header 和按钮排：

```
活动栏(48) │ 文件树(~420) │ 稿面 │ Agent 面板(~390)
                              ↑ 主角，但看上去和邻居一样重
```

量测证据：

| 指标 | Agent 面板关闭 | Agent 面板打开 |
|---|---|---|
| 屏幕上可见按钮数 | **18** | **37** |
| 稿面宽度 | 908px | 724px |
| 正文行宽 | 860px | 676px |

**打开 Agent 面板这一个动作，把屏幕上的可点对象翻了一倍。** 而稿面在视觉上并没有因此变得更"重"或更"亮"——它只是变窄了。

## 2. 逐条发现

### F1 · 标题在同一屏出现 4 次（可数）

量测：文本 `开篇：蓝梓与芥末` 在一次渲染里有 **4 处可见**：

| 位置 | 出现形式 | 坐标 |
|---|---|---|
| 顶部标签 | `开篇：蓝梓与芥末` | y=11 |
| 正文 H1 | 章标题 | y=144 |
| 左栏文件树行 | 树节点 | y=261 |
| 左栏详情面板 | `标题 / 开篇：蓝梓与芥末` | y=693 |

四处各有理由（标签是"当前打开"，树是"在哪个位置"，H1 是"文档内容"，详情是"这一章的身份"），**合起来是同一句话说了四遍**。眼睛在四个地方读到同样的信息，就学不会"哪里该看"。

→ **已部分落地**：详情面板头部改为**路径优先的单行**（`path || title` 兜底）。选它开刀的理由是精确的：详情面板的标题与正上方树行渲染的是**同一个 `props.node.title`**——这是全屏唯一**保证**重复的一对；而路径是别处都不出现的唯一信息，用它标识"这份详情属于哪个文件"零信息损失。标题仍在标签 / 树行 / H1 各出现一次，那三处各有不可替代的理由（多标签管理 / 导航定位 / 文档内容），不再动。

### F2 · 稿面第一眼是元数据，不是正文（已修）

打开一章，正文上方第一眼是一张**带描边、带底色**的卡片，内容是一行等宽字体的 YAML：

```
> title: 开篇：蓝梓与芥末        [✎] [🗑]
```

右侧还常驻一个**红色垃圾桶**（删除 frontmatter），随时待命。

这是写作工具里最"工程感"的一处：读者打开一章想看故事，先看到的是一条 YAML 和一个删除按钮。

→ **已修**（提交 `35a0890d`）：折叠态平时不描边不填底、摘要行降到 `--text-muted`、操作区（含删除）平时透明且不可点，hover / focus-within 才浮出。见 `C1-frontmatter-quiet.png` 与 `C2-frontmatter-hover.png`。

### F3 · 专注模式的初始判定是错的（已修）

这是我上一轮交付的功能，在真实界面里第一眼就是坏的：

**开启后，标题独立保持全色，正文 131 个块全部降到 28% 不透明度。** 观感是"文字被禁用了"，而不是"专注模式开着"——比不开还糟。见 `A2-light-focus.png`（修复前）。

根因：ProseMirror 打开文档时默认把选区放在文档起点（也就是章标题里），标题是 textblock，于是被判定为"当前块"。

→ **已修**（提交 `337b8493`）：标题排除在"当前块"之外，顺延到它后面第一个正文块。修复后 `B1-light-focus-fixed.png`：标题作为结构退后，正文第一段被点亮。点正文中段，高亮正确跟随（`B2-light-focus-mid.png`）。

> 这条证明了本文件夹存在的必要性：**读代码完全看不出问题，静态截图也看不出**。只有让它在真实浏览器里跑起来、点一下工具栏按钮，才会看到"整篇变灰"。

### F4 · 工具栏 6 个入口全是纯图标（已部分修复）

稿面顶部一排：分段控件（富文本/源码）、准星（专注写作）、对话气泡（评论视图）、魔法棒（扫 AI 味）、更多。**没有一个有文字标签。**

`title` 属性只在 hover 时出现——**鼠标悬停不算视觉引导**，它是隐藏式帮助。用户要在 6 个抽象图标里猜哪个是"专注写作"。

→ **已修**：「扫 AI 味」此前已带文字；本轮给**专注写作**补上图标 + 文字标签 + 快捷键提示（`Ctrl+Shift+F`）。选它开刀的理由：准星图标对写作者完全不可猜（准星 = 狙击瞄准），而它是"视觉引导"的旗舰功能——旗舰功能藏在最难猜的图标后面，是这一排最疼的矛盾。**刻意不做**的两件：把低频项收进"更多"（那是"藏起来"，NN/g 点名的失败形态）；给全部图标加标签（评论气泡、更多是通用惯例，加了只添噪音）。现在的形态是"两个带字的主动作 + 三个惯例图标"，例外比规则少。

### F5 · Agent 面板的空态是死路，不是发射台（已修）

打开 Agent 面板（状态：有可用对话但未选中），中间是：

> 请选择一个对话
> 当前实例还有可用对话，但没有可靠的上次选择。请从对话列表中选择。

**两行说明文字，零个可点对象。** 唯一的按钮在底部输入区、相距约 500px；而此刻输入框是**禁用**的，所以整屏无处可去。说明叫用户"从对话列表中选择"，却不给能选的地方。

> 注意区分：另一个空态（已选会话、还没有消息）**不是**这个问题——那时输入框可用，composer 本身就是发射台。要修的只有"未选中"这一个。

→ **已修**（提交 `b860d989`）：补「新建对话」（主）+「会话列表」（次）两个起点，正好对应正文那句话的两个出口。同时把底部 composer 状态条从指令式（"请选择一个对话后继续。"）改成陈述式（"未选中对话，输入已停用。"）——**让页面级空态负责"去哪里"，控件级说明负责"为什么这里是灰的"**，不再同一屏说两遍。空态图标也从 `status-warning` 的橙底改回中性："未选择"不是错误状态，而橙底会把注意力吸到一个没有动作的图标上。

见 `empty/W2-agent-empty.png`（改前）与 `empty/W3-agent-empty-after.png`（改后）。

### F6 · 主题：`light` 不是为写作工具设计的

`A1-light-default.png`（当前使用）与 `A3-sepia-default.png` 对比，观感差距不需要解释：

- `light` 是**纯白 + Tailwind 默认灰阶**（`--bg-panel #ffffff`、`--border-color #e5e7eb`、`--text-main #111827`）——一套框架默认值，不是设计决策
- `sepia` 是暖纸底 + 赭石橙（`#fdf6e3` / `#d97743`），跟正文的"纸"这一形态同源

而这个产品**原本的默认主题就是 `sepia`**（`resolve-theme.ts` 的 `DEFAULT_THEME_ID`）。现在窗口用的是 `light`。

→ 建议（未实施，零成本）：改回 `sepia`。暗色场景推荐 `tokyo-night`（最克制的蓝灰）。8 套对比见 `themes/00-overview.png`。

### F7 · 左栏详情面板（**经查证不是问题**）

初看像是"左栏被切成两半，下半是只读的统计与元数据"，很冗。

查证后撤回：`WorkspaceFileDetailPanel` **可关闭（`×`）也可拖拽调高**（`:height` / `@update:height`），是上下文相关的面板，不是强制常驻的 chrome。

**① 让稿面成为唯一的高对比区域** —— **已完成（`aa424195` 机制 + `710655fb` 覆盖面）**

## 4.5 repo 级问题：`/NN` 透明度后缀被静默丢弃 —— **已修（uno.config 规则）**

写 `bg-[var(--bg-panel)]/78` 这类"任意值 + 透明度后缀"时，presetUno **不应用这个透明度**。它把带后缀和不带后缀合并成同一条全不透明声明：

```css
/* 修复前，浏览器里枚举出的真实生成 CSS */
.bg-\[var\(--bg-panel\)\], .bg-\[var\(--bg-panel\)\]\/35, …\/45, …\/50, …\/60, …\/85, …\/88, …\/90 { background-color: var(--bg-panel); }
```

全仓约 150 处这种写法（bg 115 + border 33），作者写的半透明从未按预期渲染过——满屏「全强度分隔线」有一部分正是这里来的（`border-[var(--border-color)]/50` 33 处全被画成了实线）。

**上轮的「/92 /65 /95 连规则都不生成」疑点已解开**：那是 dev 模式按需生成的扫描时机——对应组件没被访问过，规则自然不存在，探针读到透明。生产构建里会全部生成（全不透明）。行为并不不一致，**统一地坏**：后缀一律被丢。

**修复**（`uno.config.ts`）：自定义规则优先级高于 preset，命中 `bg|border-[var(--x)]/NN` 即生成 `color-mix(in srgb, var(--x) NN%, transparent)`。var() 运行时才解析，主题切换、以及简洁档下本身就是 color-mix 结果的变量（如 `--border-color`）嵌套进来都合法。

**验证**（真实浏览器，同一 Agent 会话屏前后对照）：

| 类名 | 修复前实算 | 修复后实算 |
|---|---|---|
| `border-[var(--border-color)]/50` | `rgb(229,231,235)` 全强度 | `color(srgb … / 0.5)` |
| `border-[var(--border-color)]/60` | `rgb(229,231,235)` | `color(srgb … / 0.6)` |
| `bg-[var(--bg-input)]/40` | `rgb(243,244,246)` | `color(srgb … / 0.4)` |
| `bg-[var(--panel-surface)]/78` | 无规则（透明） | `color(srgb 1 1 1 / 0.78)` |
| `bg-[var(--toolbar-bg)]/95` | `rgba(255,255,255,0.9)` | `color(srgb 1 1 1 / 0.857)` |

最后一行顺带解开另一层误判：修复前的 0.9 **不是后缀部分生效**，是 `--toolbar-bg` 变量自身带 0.9 alpha；修复后的 0.857 = 0.9 × 95%，才是后缀真正参与计算。

**范围边界**：只接 `bg-` 与 `border-`（单一直接属性，声明自包含）。`ring-`（17 处）的颜色要进 `--un-ring-color` 再由 box-shadow 组合，简单声明接不住，未动；`text-`（2 处，90%/85% 与 100% 观感无差）未动。**未验证**：plot 工作台、RAG 检查器、角色详情等挂载大量 /NN 元素的界面没有逐屏截图（dev 按需渲染下这些组件不易到达）；修的是"作者意图"而非"当前观感"，如某处半透明化后对比度不足，应调那个百分比而不是回退规则。
