## 📌 TL;DR

- **整体结论：🟡 有条件通过** —— 内核（写作宪法 + World Engine + Agent 运行时）是扎实的，但工程下限没焊死，导致每加一个功能成本都在涨。
- **最扎心的一条**：项目自己造了 72 个组件 / 4 套主题 / 283 个 CSS 变量的设计系统（`packages/nb-ui`），主应用**一处都没引用**，在旁边手搓了 382 处硬编码颜色。
- **最打脸的一条**：`README.md:114` 宣称 llmlint「**既是编辑器里的润色 Skill**，也是独立 CLI」，但 `app/`（259 个组件 / 79,862 行）检索 llmlint **零命中**——对外卖的四大能力之一，作者在编辑器里根本没有入口。（主理人已复核属实；llmlint 实际以 `packages/llmlint/` 独立包 + Agent Skill 形态存在，不是功能不存在，是**承诺的入口不存在**。）
- **最危险的一条（🔴 已确认，非推断）**：**一条完整攻击链，三步可一键拖库** —— ① Portable 默认无鉴权 + 压根不设 `HOST`（Node 默认绑 `::`，所有网卡）→ ② 同局域网任何人免登录访问 → ③ 备份端点打包 `workspace/` + `.env`，**一个 ZIP 带走全部小说 + 全部 API Key + 会话密钥**。三个环节单独看都不致命，串起来是完整失陷。
- **三条必须纠正的认知**（否则会修错地方）：① `config.yaml` 里的 `server.host` **没有任何消费者**，改它无效（主理人已复核：`server/` 全量检索 `server.host|serverHost` 零命中）；真因是 `environment.ts:33` 在未传 host 时不设 `HOST`/`NITRO_HOST`；②「startup nonce」是桌面 IPC 握手，**不是 HTTP 防护**；③「动态 loopback」只覆盖 Electron/Tauri，**不覆盖 Portable**（而 Portable 正是主推分发形态）。
- **阻塞项 3 个**：设计系统闲置、主应用零 E2E、CI 门禁失效（78 条失败当基线）。
- **下一步**：先焊下限（E2E + 门禁归零），再谈体验打磨。顺序反了就是白干。

## 1. 各角色核心结论

### 🎨 设计顾问（设计系统与视觉）
- **核心判断**：这不是"缺设计系统"，是**设计系统建完了没人用**。`nb-ui` 是完整资产：72 个组件、4 套主题（`aurora` / `editorial` / `macos` / `nbook`）、283 个 CSS 变量、`tokens.ts`（116 行）、`z-index.ts`、主题版本兼容（`semver-range.ts`），还有 `e2e/` 三套视觉测试。主应用 `app/` 检索 `@notnotype/nb-ui` 与 `nb-ui|nbook/ui` **零命中**。
- **代价**：`app/**/*.{vue,ts}` 里 25 个文件有 382 处硬编码 hex、32 个文件有 235 处硬编码 px。没有 token 层 = 主题切换与暗色改造每次都是改一批文件。
- **关键建议**：不要一次性替换。选 3 个试点接管——`ProjectPickerScreen.vue`（953 行）、`NovelIdeSettingsDialog.vue`（1,342 行）、关键帧面板（刚落地、无历史包袱）。

### ✅ 质量与发布（QA）
- **核心判断**：**主应用零 E2E**。`playwright.config.ts` 只存在于 `packages/nb-ui`，主应用只有 `vitest.config.ts`；依赖里装了 `playwright-core` 却没接线。这一条直接解释了该"人写帧 UI 未经人眼确认""队列 UI 无浏览器 smoke"这类缺口为何反复出现——不是谁偷懒，是**工具链层面就没有覆盖主链路的手段**。
- **门禁已失效**：Full tests 有 24 文件 / 78 失败的既有基线（POSIX `C:/...` 伪路径门禁），长期未清零。红灯天天亮，就没人看红灯了。
- **关键建议**：① 主应用建 `playwright.config.ts`，先跑 3 条冒烟（打开→选项目→写一节；关键帧面板 tab 切换与新建；Agent 会话发起与中断）；② 78 条失败要么修、要么显式 skip + 登记 Issue，让"红灯=真问题"回归；③ 224 章 / 322 场景规模下补性能预算。

### 🛡️ 安全官（OWASP + STRIDE）——本节由成员 `gstack-security-officer` 产出，主理人复核了其中两条关键证据

- **核心判断**：**不是三个孤立漏洞，是一条链**。🔴3 / 🟠3 / 🟡4 / 🟢4。

**攻击链（F-001 → F-002 → F-003）**

| 环节 | 事实 | 证据 |
|---|---|---|
| ① 门没锁 | Portable 默认无鉴权；且**压根不设 `HOST`** → Nitro 取 `undefined` → Node 默认绑 `::`（所有网卡含 IPv6） | `cli.ts:112`；`environment.ts:33` 的 `...(host ? {HOST, NITRO_HOST} : {})` |
| ② 钥匙在桌上 | Provider API Key **明文落盘**——本机 State Root `config.json` 实测 **4 个非空 Key** | `config-service.ts:87-89 / 1305-1310 / 1561-1564` |
| ③ 打包带走 | 备份打包 `workspace/` + `.env` → 一个 ZIP 含全部小说 + 全部 API Key + 会话密钥 | `backup-archive-service.ts:14, 98-101` |

- **主理人已复核的两条**：① `environment.ts:33` 确认——只有传入 host 才设 `HOST`/`NITRO_HOST`，Portable 走缺省分支；② `server/` 全量检索 `server.host|serverHost` **零命中**，证实 config.yaml 那个配置无人消费。
- **另两条新增（未在初版清单里）**：🟠 Agent 绝对路径可绕过容器边界 + bash 无门禁（打开恶意项目即可被提示注入打穿）；🟠 无 Host/Origin 校验 → DNS rebinding 可行。
- **🚫 别动清单（这几处做得比同类项目好，别改坏）**：scrypt 密码哈希、登录防爆破四件套、`projectRoot` 路径穿越防护、`realpath` 容器校验、Electron 沙箱。
- **成员三条建议**：① Portable 启动强制 `HOST=NITRO_HOST=127.0.0.1`（照抄 `source-dev.ts:86`），并加「非 loopback 且鉴权关闭则拒绝启动」的 **fail-closed**；② 备份默认剔除 `.env` 与 `config.json` 的 apiKey，备份端点显式 `requireAdminAccess`；③ API Key 用 Windows DPAPI 加密落盘。

### 🔍 产品评审（本节由成员 `gstack-product-reviewer` 产出，主理人复核了其中最关键的一条）
- **核心判断**：四大能力里，**用户首屏能感知的是 0 个**。四大能力都造好了，但都装在后盖里——不是打磨问题，是**首屏价值交付断裂**。

- **🟠 第一步就不存在**：`README.md:108` 卖的默认链路第一步「灵感探索」，前端 i18n 检索为空。（成员报告，主理人未逐条复核）
- **🟠 「体验打磨」无终点**：`PROJECT-STATUS.md:47` 全仓无 DoD。
- **成员三方案**：① **空态即演示**——新书不给空白页，预置一本 3 章示例书（含 1 个未兑现伏笔 + 5 处 AI 味），用户打开即感知全部能力，零配置，投入产出比最高的一天工作量；② llmlint 加编辑器入口；③ 用 **5 条 Journey 看板**取代"体验打磨"这个词（J1 首字 90 秒 / J2 AI 首章 10 分钟 / J3 续写 20 秒 / J4 伏笔闭环 60 秒 / J5 扫 AI 味 2 点击），每周用 224 章真稿跑 6 条断言、产出可 diff 的 JSON，作者每周只看 10 分钟。
- **边界声明**：本评审**不评判写作方法论**（关键帧写作对不对、事前告知还是事后校验）——按写作宪法，"什么叫好"只有作者能判。
