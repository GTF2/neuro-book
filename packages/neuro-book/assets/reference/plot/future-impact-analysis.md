# 未来影响分析（Future Impact Analysis）

正文一旦被采纳为 canon，它就可能**让下游规划失效**：某条承诺的兑现已经不可能、某个后续场景与事实冲突、某个已声明关键帧被正文推翻、某个期限已经落空。本 Reference 给出这件事的运行期合同：什么时候跑、扫哪些面、清单长什么样、谁裁决、不做什么。

它**只标记、不改动**。判断权留在作者与 leader（写作宪法第六条）。

## 它与反向核对的分工

| 方向 | 做什么 | 谁做 |
|---|---|---|
| 反向核对 | 正文 vs 已声明：正文有没有漏写、有没有越界、有没有与设定冲突 | 三维评审、`consistency-audit` |
| **正向扩散（本能力）** | 新事实 → 下游规划：这个事实让哪些尚未写到的计划不再成立 | leader（本文） |

两者不互相替代：反向核对盯"已经写了什么"，本能力盯"还没写、但已经不可能照原计划写"。

## 什么时候跑

在正文循环的**修订之后、完成标准之前**，且**本章本轮产生了新事实**时跑。典型新事实：

- 事件结果被改写（谁赢了、谁没来、事情提前/延后了）；
- 物品易主、损坏或消耗；
- 角色位置、伤势、能力状态变化；
- 信息披露（某个秘密被提前说破，或本该说破的没说）。

本章没有新事实时不必跑，直接返回"无需分析"——**不要**产出空清单冒充"已核对"（见失败语义）。

## 三类扫描面

三类都要扫，全部用**只读**工具，逐面给出结论（有则列条，无则显式写"未发现"）。

### 1. Promise 面

- 工具：`get_story_promise`。
- 看什么：
  - 本章 Scene 上挂了哪些 `PromiseBeat`（计划推进的债务线）；
  - 有没有未兑现、且 `deadlineChapterId` 已过或临近、或 `cadenceChapters` 节奏已经落空的 Promise；
  - 新事实是否让某条 Promise 的**兑现场景在物理上不可能**（人或物已经不在原定位置/状态）。

### 2. Scene 面

- 工具：`get_story_thread` / `get_story_scene_context`。
- 看什么：
  - 本章之后、同 Thread 的后续 Scene，其描述是否与新事实冲突（同一时间窗角色出现在两处、已死的角色还有戏、已易主的物品还在原主手里）；
  - 相邻章 Scene 的 World 锚点与新事实是否相容。

### 3. 帧面

- 工具：`get_story_keyframe` / `get_tween_keyframes`。
- 看什么：
  - 本章是否落在一对已声明关键帧的补间区间内；
  - 区间内帧声明的 `irreversibleChanges` 是否被正文**推翻**（应发生的不可逆变化没发生，或发生了与声明相反的变化）；
  - 若被推翻，提示后续必须按宪法第六条走**推翻留痕**（`save_story_decision` + `save_story_keyframe` 的 `status=overthrown` + `decisionRefId`），这一步不由本能力自动完成。

## 清单格式

结构化数组，每条四字段：

| 字段 | 含义 | 取值 |
|---|---|---|
| `target` | 受影响的下游对象 | Promise / Scene / 关键帧 / 章 的身份（id 或 name + 人读标题） |
| `impactType` | 影响类型 | `promise_unfulfillable` / `scene_conflict` / `keyframe_overthrown` / `deadline_missed` |
| `evidence` | 证据 | 引用正文原句或规划数据的具体字段，可被核对；不写"感觉可能" |
| `suggestedAction` | 建议动作 | `改计划` / `保持` / `待裁决` |

## 人读 Markdown 模板

```markdown
# 未来影响分析 · 第 N 章《章名》

本轮新事实：
- （逐条列出）

## Promise 面
- [promise_unfulfillable] 承诺「…」（deadline: 第 M 章）
  - 证据：正文「…」
  - 建议：改计划 —— 兑现地点/方式需重排，或声明延期

## Scene 面
- [scene_conflict] 后续 Scene「…」（第 K 章）
  - 证据：该 Scene 要求「…」，与本章正文「…」冲突
  - 建议：待裁决

## 帧面
- [keyframe_overthrown] 关键帧「…」（instant …）
  - 证据：帧声明「…」不可逆，正文「…」显示未发生
  - 建议：改计划 —— 按宪法第六条走推翻留痕

## 未发现
- （某一面无受影响项时，在此显式写明"未发现"，不要省略该面）
```

## 逐项裁决

清单交给**作者与 leader** 逐项确认，每条选"改"或"保持"：

- 选"改"的项，走既有写入路径：`save_story_scene` / `save_story_promise` / `save_story_keyframe`（推翻帧时另配 `save_story_decision`）。
- 选"保持"的项，视为作者接受正文与计划的偏差，不写入。
- 本能力**不落库、不自动改规划**：裁决结果由人发起后续写入。

## 失败语义（fail-closed）

- 某面只读查询失败：明确报告**"该面未完成核对"**，不产出"看起来干净"的空清单——绝不能把"没查到"说成"没有问题"。
- 部分面成功、部分面失败：整份清单标注失败面为"未完成"，并要求重跑。
- 本章无新事实：返回"无需分析"，这是**有效的正常结果**，与"查询失败"必须可区分。

## 不做什么

- 不自动修改 Scene / Promise / 帧 / beat。
- 不做"全文一致性证明"（那是反向核对的事）。
- 不引入世界版本冻结 / 派生世界。
- 不改 writer 的动笔前上下文（与宪法第二条无关）。

见 `novel-writing/phases/03-chapter-loop.md` 的「未来影响分析」步骤：修订之后、完成标准之前执行，产出清单并逐项确认后，本章才算收口。
