## 四、跨任务模式（作者画像）

1. **三次大转向，每次硬切不留尸**：RP 起家（01）→ emulation 模拟线（31/32/42）→ 写作模式硬切（121 把 simulation 归档、World Engine 成唯一真相源）。"硬切"是他的高频词：roleplay→simulation、novel-api server 集成、PG 移除，全部不留双轨。
2. **口头禅四件套**（README 里反复出现）："不要 hack 系统性修复"、"硬切不留兼容"、"先计划+审问再实现"（$grill-with-docs）、"多方案对比后拍板"。且用户（作者本人）频繁显式纠偏 AI 的过度设计（05/91 两次"砍掉我提出的复杂方案"）。
3. **极致 dogfooding**：用这个软件的 Agent 体系开发这个软件（91 号"由本任务产出 goal 文档派发给其他 agent 实现"）；性能问题全是自己真用打脸出来的（8s 列表、5GB OOM、MB 级 JSON、压缩失败）。
4. **基建 >> 产品**：引擎室（A+B+C 组 ~52 任务）投入是 UI/引导（H 组 ~10）的五倍。可靠性长期主义（73/74/106/107/147 连绵不断）。
5. **烂尾名单**：emulation 线（31/32/42）、sidecar 能力（23→116 收缩）、ChapterOverride（Task 80 规划从未落地，87 号提及）、"先写后补"模式（91 起点，未成产品）。
6. **对 009 的意义**：作者已用行动回答了"该不该做引导"（没做过）、"设置该不该减"（他自己加的二级菜单只是缓解）；而"先写后补"是他自己立过项又没做完的——**咱们 009 若做"边写边攒/AI 代填"，等于替作者完成他自己的心愿，方向冲突风险低**。
