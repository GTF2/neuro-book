## 四、从数据看出的观察

1. **前端重量高度集中在 novel-ide 域**：73% 的组件代码在 `novel-ide/`，且 Top 20 大组件里 16 个属于它。IA 重构的主战场就是 novel-ide 一个域。
2. **单体巨组件模式**：最大 5 个组件全部 >1900 行且只被 1-3 个文件引用——它们是"页面级组件"，实际承担了页面/布局/状态管理三重职责，而非可复用组件。`AgentChatSurface.vue`（4454 行、仅 1 处引用）是典型。
3. **路由 IA 名义上"只有 4 个页面"**：真实业务路由仅 `/`、`/login`、`/admin/*`。产品的主界面（IDE、plot 工作台、world-engine 工作台、profile 编辑器等）全部塞在 `/` 之下由组件切换，没有路由表达——这与前任"病根在信息架构层"的判断一致：**功能入口无法用 URL 寻址、无法用路由守卫分层、面包屑/回退/深链全部缺失**。
4. **14 个 preview 路由是事实上的组件目录**：`*.preview.vue` 平铺在 pages/ 顶层，与业务路由混在一起。它们既污染路由命名空间（`/plot.preview` 等），又说明开发沙箱没有独立的挂载机制。
5. **大组件被引用数极低但深度嵌套**：world-engine/workbench-preview 下 5 个大组件仅服务一个 preview 路由，说明"预览页→巨型组件"的成对膨胀；重构时应按"域→工作台"两级收敛，而不是按组件拆分。
6. **server 侧 agent 子域是后台最重模块**（106k 行，占 server 的 40%），与前端 agent 聊天/会话面（AgentChatSurface、AgentComposer、AgentSessionTreeDialog 等）对应，横切 novel-ide 的每个工作台——IA 重构需要把"agent 能力"当作横切服务而非某个面板。
