# 安全体检大白话总结（写给完全不懂技术的人）

> 2026-09-20 深夜做的全仓库"安全体检"。完整技术版在 [REPORT.md](REPORT.md)。这里只说人话。
> 先说安心的部分：**没有发现任何"密码或钥匙被写在代码里"的问题，git 历史也干净**。下面按"多紧急"分三档。

## 🔴 严重（建议这周就处理）

**1. 别人的"小说项目"文件夹能在你电脑上运行程序。**
软件会把项目文件夹里的某些"配置文件"直接当代码执行，而且**你一打开这个项目它就执行了，不会问你**。也就是说：如果你从网上下载、或者别人分享给你一个小说项目，里面有坏人藏的东西，打开就中招。
👉 **怎么办：来路不明的项目包先别导入打开；等前线把"系统文件夹禁止写入"这个补丁打了再恢复分享玩法。**

**2. AI 干活时几乎没有"围栏"。**
AI（Agent）可以执行命令、可以写代码，本该有的两道锁：一道根本没接线（摆设），一道只读模式能绕过。极端情况是：AI 被小说文本或网页里的恶意指令"骗"了（这叫提示注入），就能在你电脑上为所欲为——读文件、删文件、联网。
👉 **怎么办：短期内别让它处理完全不可信的大段外来文本时撒手不管；修复很简单（各加一行代码），已写进报告。**

**3. 依赖检查补跑完了：81 个小毛病（1 个红的、29 个橙的）。**
真正要紧的只有一个：开发用的调试工具（Nuxt DevTools）有个洞，坏蛋能在"开着开发服务器的电脑"上执行命令——只影响开发者跑 `bun run dev` 的时候，**不影响你平时用这个软件写小说**。另外网络组件 undici 带了几个中等问题。其余 70 多个都藏在构建和测试工具里，不碰产品本身。
👉 **怎么办：升级几个包就能清掉（`bun audit fix` 加三处手动升级），清单在技术报告 05 号文件里，留给前线排活。**

## 🟡 要紧（找个时间修，不急但别忘）

- **开发模式默认"不锁门"**：本机自己用没事；但千万别手贱把服务开到"局域网可见"，那样同一 WiFi 的人能完全控制软件。
- **聊天窗口渲染有个小豁口**：AI 回复里若被塞了恶意网页代码，有机会在界面里执行（被桌面壳的沙箱挡住，偷不到系统权限，但能乱动界面和本地接口）。加一行同步加载的消毒代码就能堵上。
- **llmlint 网站（就是部署在公网那个）没有防刷屏机制**：登录用户可以无限灌数据烧服务器存储和 AI 额度。
- **一个待查项**：网站报错时可能把含密钥的错误信息原样显示出来，还没查实。

## 🟢 可缓（知道就行，记在账上）

- 服务器真实 IP 和部署细节写在了几个文档里，仓库又是公开的——等于告诉别人"门牌号"。建议下次提交顺手改掉。
- CI 里有几个明文测试口令——查过了，是一次性的，用完就扔，不算泄露，但别抄去正式环境用。
- AI 服务的钥匙（API key）是**明文存在你电脑的配置文件里的**——这是本地软件的常规做法，防线上泄露的措施都做了；但**备份或网盘同步 `.nbook` 文件夹时记得里面有钥匙**。
- 另有七八个"睡觉"的小隐患（没被用到的代码入口、可收紧的配置），都登记在技术报告里了。

## 一句话总结

这套软件的安全基本功（防 SQL 注入、防路径穿越、密钥掩码脱敏、桌面壳配置）**做得相当规范，明显下过功夫**；真正的软肋集中在"AI 执行代码缺围栏"和"项目文件能变程序"这两件事上，而且**修复成本都不高**（最小改动是加两行代码）。清单和修法都在 [REPORT.md](REPORT.md) 里。
