# 04 前端与桌面端

> 范围：packages/neuro-book 前端（app/）、nb-ui、desktop/electron、desktop/tauri、packages/owned-process、neuro-agent-harness（接口面）。方式：源码级只读审计。
> 结论一句话：**Electron/Tauri 的壳配置做得很规范；前端渲染链有一条主通道 + 几个"睡着"的旁路需要处理。**

## 4.1 前端 XSS

### Agent 气泡 markdown（要紧偏低）

- 渲染链：`app/utils/markdown/render.ts:266-273` —— `renderMarkdown(content, sanitizeHtml?)`，**sanitizer 缺省时原样透传**；marked 本身不消毒。输入是 LLM 输出（提示注入可控）。
- 唯一生产调用点 `AgentChatSurface.vue:3777` 在 `onMounted` 里异步 `import("dompurify")` 后才 provide —— **导入完成前的渲染窗口期不消毒**（窗口极短，但首条流式消息理论可落进去）。
- `AgentMarkdownContent.vue:25` 的 **props.html 直通分支完全绕过 sanitizer**（当前无生产调用者，属休眠旁路）。
- 后果边界：Electron renderer 有 sandbox + contextIsolation，劫持后是 renderer 内脚本执行 + 同源本地 API/过 origin 校验的 IPC 调用权，**不是直接 RCE**。

**修复**：dompurify 改构建期静态导入（同步可用）；删除或消毒 props.html 分支。

### 其余注入点（可缓）

- `NotificationViewport.vue:147` `v-html="item.html"`：无消毒通道，当前**无生产者投喂**——休眠活体注入点，谁将来传服务端文本谁就造出裸 XSS。建议改结构化字段。
- `WorkflowMermaid.vue:26` v-html 渲染 mermaid SVG：未显式 `securityLevel: "strict"`（needs_validation，见 findings.json）。
- `HtmlEmbed.ts`（手稿内嵌 HTML）：iframe `sandbox="allow-scripts"`（opaque origin，碰不到父页）+ postMessage 桥校验 source + 数据桥默认关闭——**当前干净**；两条前瞻红线：内嵌 HTML 可在沙箱内跑脚本；回包 `postMessage(..., "*")`（:267）——将来若启用 dataApi 必须收紧 targetOrigin 与数据白名单。
- 干净的：AgentTextBubble（textarea 解码实体，RCDATA 不执行）、nb-ui svg-defs（显式标签白名单 + 安全论述）、web-tools 的 innerHTML 是内容提取非 DOM sink。

## 4.2 Electron（壳配置——干净）

- `desktop/electron/src/main.ts:949`：`nodeIntegration:false, contextIsolation:true, sandbox:true, webSecurity:true`；manager 窗口同配置。
- 导航守卫：`setWindowOpenHandler` 一律 deny；`will-navigate` 仅放行本地 loopback origin。
- IPC 全部 `assertTrustedFrame`（校验 senderFrame origin）+ 入参白名单/枚举；preload 经 contextBridge 最小暴露。
- manager:run 先 `validateManagerOperation`，安装/启动以 manifest + sha256 回执复核。
- **注意**：信任锚是 product 页面 origin——**一旦 4.1 的 XSS 成立，这些 IPC 防护对攻击者同源可用**（窗口控制、settings merge、appearance）。`patchDesktopSettings` 合并实现未定位到（needs_validation，若为递归 merge 有原型污染面）。

## 4.3 Tauri（干净）

- `windows: []` 占位 frontend；无 shell/fs/opener 插件；capabilities 仅 `core:event:allow-listen`。
- 低危注意：CSP 含 `'unsafe-inline' 'unsafe-eval'`——当前无真实窗口内容，接入真实页面时应收紧。

## 4.4 owned-process（子进程托管，基本干净）

- 回传协议逐字段类型校验 + 终止原因白名单（windows/posix-adapter）。
- **设计取向注意**：目标进程 env 由调用方决定，desktop 侧为"全量展开 process.env 再剔除少数"（剔除 `AUTH_ADMIN_PASSWORD` 等），非白名单放行——密钥类环境变量默认全量下发给子进程。建议转白名单式。
