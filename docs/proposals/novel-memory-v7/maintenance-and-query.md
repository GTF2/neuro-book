# V7 维护、查询与工程落地

状态以 [提案入口](../novel-memory-v7.md) 为准；记录语义以 [知识模型](knowledge-model.md) 为准。本文规定候选方案的执行与一致性边界，不声称已有实现。

## 1. 整理分工

处理阶段共享同一套候选变更、验证、依赖与发布机制，不各自拥有一套记忆 schema。查询 Agent 不承担重建跨章图的默认责任。

| 阶段 | 输入 | 可产生的结果 | 可见性 |
| --- | --- | --- | --- |
| 导入 | 原文、目录、作品/分支身份 | SourceRevision 与材料清单 | 原文就绪可查询，提取状态另报 |
| 章级 ingest | 编号原文、必要前文、有限旧对象候选 | Referent、Disclosure、Beat、局部身份/Fact/情节候选 | 完整材料批验证后发布；知识未完成不冒充 ready |
| 增量整理 | 新材料、受影响对象和既有知识 | Resolution、Fact、跨章 Episode、局部综述、重审与 Watch | 通过评估的知识批原子发布 |
| 梦境 | 有目标的跨区域材料集合与当前问题 | 身份优化、规则归纳、跨章联系、主线综述、反证、知识修正 | 与增量整理使用相同验证，权限不更高 |
| 查询 | 发布快照、范围、查询意图 | 知识、材料、证据、状态、覆盖及游标 | 不发布回答中的临场推断 |

章级 ingest 可以复用已确认身份、形成清晰的局部 Fact；跨章整合无需拖到梦境。材料提取可按章并行候选化，但发布串行；跨章指称和过程由后续增量整理统一，允许重复候选，不允许静默同名合并。

“章级”是输入组织，不是记录范围限制。跨章连续场景可以给前章尾部作为显式上下文；所有被使用的上下文都进入 provenance。超长章按完整 Beat 分批，单 Beat 超限须重新分片或进入长文本处理，不能截掉原文后宣称全章完成。

## 2. 从输入到发布

### 2.1 材料输入包

输入包固定 sourceManifest、章节版本与位置规则、上下文 Span、候选对象版本、prompt/schema/policy 版本。模型可见的已知引用采用白名单；候选描述也必须带来源，不能把无证据人物简介当作原文。

初次抽取默认使用当前章及必要前文；回访可以使用全书材料。后一种结果用于历史 readAt 时，依知识模型第 6.3 节经过相应范围复核。运行能看多少、结论在什么范围可用分别记录。

提取粒度由材料价值决定：持续主体、关系变化、规则、重要行动与转折优先进入知识；其余内容至少可经 Beat/原文检索。语义遗漏审核按原文与提取对照，不能用“每段都有 Beat”证明关系与设定已覆盖。

### 2.2 候选变更集

```text
ChangeSet
  operationKey, baseKnowledgeRevision, sourceManifest
  readSet: 消费的记录/词项/身份/覆盖 revision
  creates: 新记录、具体版本及论证
  supersedes/retracts: 被替代版本与理由
  resolutions: 精确的指称归属变化
  watches: 新增/关闭的重审关注项
  validation: 结构检查与语义复核记录
  coverageDelta: 实际处理范围及失败/未处理部分
```

模型只提交结构化数据，不执行 TypeScript、shell、SQL 或任意工具指令。正式 schema 可采用 JSON 数据验证；输出语言不参与领域语义。程序检查结果不能补造语义事实，格式修复须留原始输出及新尝试。

发布顺序：

1. 固定输入，保存调用尝试和输出。
2. 验证引用、证据范围、原文版本、论证无环、作用域与参数。
3. 依知识模型第 7.4 节完成相应语义复核；争议项目可保留候选。
4. 基于当前已发布版本计算完整变更及受影响根；验证 readSet 仍有效。
5. 在一个短事务中检查任务尚未取消、executionGeneration 仍归本 Worker、head/readSet 有效，再插入不可变记录、变更状态、依赖和失效根、覆盖记录、待运行任务与发布 revision。
6. 事务后更新可重建索引。未就绪索引单独报告；正式结构查询不依赖向量成功。

同一批语义相互依赖的身份、Fact、情节参与者一起发布。互不依赖的条目可分批，覆盖范围必须精确到实际完成项。材料成功、身份整理失败时保留材料，返回 `knowledgePending`，不伪造全章知识完整。

### 2.3 接受与人工修正

系统自动处理可复核的知识，不要求开发者逐项审核每次梦境。候选冲突或反复失败留下可查询的问题，必要时供人工检查；任务失败不强迫用户马上回答。

人工纠错有两种语义：纠正提取/归并时附原文依据，走相同版本和依赖机制；人工新增原文之外的设定标为 editorial 或分支假设，不能混成原作披露。查询 Agent 临时推断不自动入库；未来若提供建议回写，仍要经过 ChangeSet。

## 3. 重审与撤回

### 3.1 具体依据与关注范围

Argument 的具体版本用于复现和失效；Watch 用于发现新东西。Watch 至少描述对象/关系族/事件/主题范围、待解问题、检索词与必要别名、上次检查的材料水位、触发原因和优先级。

例如“这两个人是否已成为朋友”的 Argument 钉住纸条、应答和加好友材料；Watch 可以关注后续双方互动。新材料被召回不自动成为旧 Argument 的前提，只触发新的评估版本。

所有知识不需要人为逐项建 Watch：系统根据结论依赖、关系族和参与者自动登记基础订阅；复杂未决问题再补语义 Watch。没有命中任何旧对象的新章也参与轮转覆盖审计，避免名字变化导致永远召回不到。

### 3.2 变化分类

| 变化 | 应做的事 | 不应得出的结论 |
| --- | --- | --- |
| 重复表达 | 新增材料，与同命题支持关联 | 重复次数证明更真 |
| 新身份揭晓 | 新 Resolution 理由，更新可用范围 | 后文名字从第一章起可见 |
| 实际状态变化 | 新时段命题，与旧观测关联 | 原来的状态记录是错误数据 |
| 角色否认/不同来源冲突 | 新反证或来源观点，重评世界判断 | 后来的话一定胜出 |
| 提取器误读 | 替代/撤回错误提取版本，失效依赖 | 文本自己改了说法 |
| 原文修订/删除 | 新 manifest，旧位置在旧版保留，重建受影响材料 | 段号相同仍是同一句 |
| 词义/归并策略纠正 | 新语义映射版本、依赖失效 | 只改 UI 标签即可 |

### 3.3 失效传播

依赖表至少记录：结论组件 revision、Argument、前提记录 revision、身份/词项/时间映射、前提 Assessment revision，以及所使用的来源 manifest。支持和反对都算依赖，不能只传播正向证据变化。

前提撤回或有新反证时先标记受影响评估需要重审，再通过反向依赖找后继。多个支持路径中一条失效，不自动抹掉其他路径；重新评估剩余路径的完整性和反证。只有独立可用路径足以支持且复核仍有效时，结论维持 accepted。无法即时判断则 stale，查询明确返回待重审信息。

反证新出现属于“原先读集没有这个记录”的变化，由 Watch/对象分区的变更水位触发；不能只检查已存在前提的版本相等。至少将同主体与关系族、身份候选集合、时间范围的相关评估标待重审。关联关系未被语义召回发现的漏项属于质量风险，通过覆盖审计检验，不能宣称程序能确定所有自然语言反证。

### 3.4 先阻止旧结论继续冒充当前，再异步重算

大范围依赖遍历不能长期占住写事务。发布事务先写失效根及其 generation，并推进相关分区的材料水位；后台分批遍历依赖，重建 Assessment 和索引。

查询不能仅相信旧行的 `ready` 字段。每条返回的解释需通过当前快照的有效性保护：其依赖闭包未命中尚未处理的失效根，且该闭包内每个前提和 Assessment 的 Watch 分区都没有待处理的新材料水位。发布新材料时登记的分区失效根也参与这项检查，无须等待后台先定位某条 Fact。缓存必须同时绑定记录依赖 generation 和闭包订阅的分区水位；检查超出上限时标 pending/stale，不按 accepted 返回。

这保证已登记的变化不会在重算窗口泄漏旧结论；不保证模型发现了每一个语义关联。没有变化的分区保持可用。原始材料可以继续查询，当前答案同时报告哪些知识受影响。

## 4. 梦境阶段

### 4.1 触发与输入范围

三种触发共存：新材料/冲突引发的增量任务，空闲时按保存游标轮转主题或实体范围，用户明确要求重整某个范围。查询发现覆盖缺口可以登记需求信号，但只读查询不自行发起付费模型调用。

每次梦境有明确问题、范围、输入快照、输出上限和停止条件。例如“检查近期与苏天晴互动的实体是否有重复身份”“整理截至第 20 章力量来源与限制”。不给模型一个无限制的“继续想”，也不要求每次全量加载整书。

输入由结构邻接、名称/别名、关键词、语义召回及覆盖扫描组合。先小范围，再在证据不足时有记录地扩大；召回截断必须保留标记。无名称锚点的主线和世界观问题通过主题与章节覆盖计划取材，不只沿已知人物图扩展。

### 4.2 产物与权限

梦境可提出新命题、实体拆合、关系整理、Episode 重组、规则归纳、综述和问题关闭。所有产物带理由、具体输入版本与受影响范围，走同一发布路径；不能改写原文、伪造 Disclosure 或把自己的上轮话算作新证据。

无新材料仍可发现遗漏联系，允许新增推断；其证据根不增加。输入、策略和问题相同且上轮无变化时保存 no-change 结果并降低该任务优先级，直到新证据、策略变化或明确重跑。不能因为模型换种措辞就形成无限新 Fact。

初版按一次有限任务执行一轮候选生成、一轮所需复核和确定性发布。发现新问题可排后续任务，但每次调度有调用/token/耗时/输出条目上限；达到上限返回未完成范围和可恢复游标。具体数值在真实运行前配置，不能用“全书整理完成”作为唯一停止条件。

## 5. 查询合同

### 5.1 所有查询共有的上下文

| 项 | 默认和行为 |
| --- | --- |
| book / sourceManifest | 必须确定一本作品及版本；不跨作品混合身份 |
| knowledgeRevision | 默认该 sourceManifest 的兼容 head；显式不兼容组合返回错误，一次多步读取和分页固定它 |
| readAt | 缺省表示所选 manifest 的全部已导入材料；显式位置限制证据和解释可见性 |
| storyAt / storyRange | 缺省表示不筛故事时点；限定时返回匹配、不匹配或无法定位 |
| perspective | 默认综合来源；可筛某人物认知或指定来源，不等于只保留该角色的台词 |
| scope | 默认原作世界；书中梦境、引用故事、假设分支有各自范围 |
| epistemic inclusion | 默认 ready accepted 为主，同时返回相关争议、候选与未就绪提示 |
| limit / cursor | 有限返回；游标绑定快照、范围、排序、查询摘要及检索视图身份，详见第 8.1 节 |

默认全部已导入材料不等于原作整本已导入，响应必须给 manifest 预期与实际导入覆盖。调用者指定 readAt 超过已导入范围时返回范围不足，不能把请求位置当作处理完成水位。

时点不明的知识可以进入单独 `unplaced` 组，不混入“此时成立”的确定结果。调用者可选严格匹配以排除它，但覆盖提示仍说明存在无法定位项。故事时间未给时不默认返回“最新状态”，而是返回观测和关系时间范围。

### 5.2 能力面

下表是语义能力，不冻结工具名，也不提供任意 SQL/Cypher 或任意代码执行。

| 能力 | 输入 | 返回 |
| --- | --- | --- |
| 找对象 | 名称、描述、类型/上下文线索 | 候选实体、可见称呼、歧义及身份依据 |
| 查知识/关系 | 对象、关系族、参数角色、范围 | 完整 Fact、相邻对象、时间、评估、依据入口 |
| 列集合 | 类别或成员条件、范围、游标 | 已整理成员与成立依据，歧义项、已穷尽状态 |
| 查情节 | 参与者、主题、事件线索、范围 | Episode、过程步骤、材料、因果/时间依据及边界 |
| 查综述 | 主题、尺度、覆盖范围 | 主线/世界观/力量体系等条目和缺口 |
| 查实体摘要 | 实体、facet、阅读边界、故事时间和视角 | 可重建的 EntitySummary；逐条依据、覆盖、缺口和新鲜度 |
| 搜索材料 | 词语或语义、记录类型、范围 | Disclosure、Beat、原文片段及匹配类型 |
| 展开依据 | 记录 revision、深度/条数限制 | 支持与反对、具体前提、共享来源和继续游标 |
| 读原文 | 固定版本的 Span 与上下文范围 | 原文与准确坐标；超 readAt 部分不返回 |

多跳查询由 Agent 组合这些能力；每跳保留返回的身份与 scope，不把一条候选身份默认为已确认后继续确定性跳转。结构关系图不能把 about 共现边伪装成朋友/敌对/隶属边；如展示共现必须单独标示。

类别集合的 canonical 匹配集合包括直接成员和知识模型第 4.2 节定义的有限上位类别成员闭包，不仅是直接存储同一个类别 ID 的行。查询固定分类映射版本，返回成员的显式或派生依据；分类歧义单列，类别展开超限标不完整。同一个实体经两条类别路径命中只计一个成员，保留两条解释。

### 5.3 响应最低信息

```text
result
  snapshot: sourceManifest + knowledgeRevision + effectiveScope
  items: [{recordRevision, content, assessment, timeFit, provenanceHandle}]
  relatedUncertainty: 有关争议、未消歧和待重审提示
  coverage: imported / extracted / integrated / reviewed / indexed 的实际范围
  completeness: recordsExhausted + corpusClosed + semanticCoverageNote
  truncation: limit | depth | budget | indexUnavailable | none
  nextCursor, pendingWork
```

`recordsExhausted` 仅表示在所选查询和快照中，canonical 匹配集合已经分页遍历完；投影缺项或受限扫描未完成时，即使该投影已无下一条也只能是 false/unknown。语义相似搜索的 top-k 耗尽不能声称 canonical 全匹配集合穷尽。`corpusClosed` 只来自明确的封闭文本集合及其依据，例如原文明确枚举委员会仅三人；通常为 false/unknown。处理完所有章仍不证明语义抽取没有遗漏。

展开证据默认短摘要，允许继续到原文根；不强迫每个回答展开全部推导链。推导很深时不得只丢掉前提，需返回截断和句柄。

### 5.4 历史范围与索引

实体摘要是独立的派生查询投影；V4 的主体介绍在此成为可按实体与范围直接命中的记录，而不是每次扫描所有 Fact 后现场拼接。实际字段、索引布局、重建触发与小样本测量见 [schema 与查询投影](schema-and-projections.md)。摘要缺失时允许展开已整理知识，不能拿全书简介冒充早期简介。

先建立范围内的可见材料/解释候选，再排序和分页。不能先全书 top-k 后过滤，也不能用未来名称、全书人物简介或未来反证给早期候选排序。

关键词索引按材料/解释 revision 存储；向量按文本、模型和作用域版本缓存，原文未来部分不得参与早期片段向量。若索引不支持可靠的范围前置过滤，使用过滤后的确定性候选集评分或声明该检索路不可用，不能仅 overfetch 后谎称满足可见性。

全书训练好的通用模型常识无法技术上消除，但系统提供的小说证据、词项和实体上下文必须遵守范围。知识模型第 6.3 节的复核约束用于防止系统自己的后文解释混入早期结果。

## 6. if 线资料

分叉锚点是作品版本中的具体叙述位置或明确故事事件边界。“第九章开始”通常可先定位章首，但若该处是回述、并行线或时间锚不明，不能把章节顺序当世界切片；返回候选锚和局部顺序限制，Agent 按写作任务决定进一步定位。

允许全书材料参与，但结果分为：

1. 已有依据表明在分叉前或分叉时成立的背景；标注是否后文才披露。
2. 分叉时角色知道、相信、怀疑的内容及未知项。
3. 原作分叉后的事件与变化，标为原作延续参考。
4. 无法安放到分叉前后的材料与推断。

第 1 组的判断需要时间依据；“后文提到某能力”不自动证明分叉前拥有。第 3 组不能用于推出 if 线必然未来。实际分支写作产生的新材料单独保存 scope/manifest，后续是否从原作继承哪些事实由显式分支选择决定；本轮不设计自动分支世界模拟器。

## 7. 存储与索引的可行方案

### 7.1 首轮推荐布局

一个作品资料库使用一个本地数据库管理 canonical revision、Argument、Assessment、Resolution、依赖、ChangeSet、覆盖与任务；大原文和模型原始输出可作为不可变 blob 存放，数据库记录内容哈希及相对位置。任何数据库引用的 blob 必须先持久可读，再提交引用；未提交的孤立 blob 可后续回收，本轮不定义删除策略。

关系邻接、参数倒排、名称与全文索引、向量、闭包有效性缓存和展示摘要均为投影，可从发布记录重建。即使 sqlite 索引表和 canonical 表在一个库，它们的权威地位仍不同。JSON 导出包含 schema 版本、manifest、发布记录、依赖和校验信息，导入按依赖验证；导出不是另一个可并写真相源。

选择 SQLite 是工程建议：SQLite 对同库写入串行化，WAL 可让独立读连接读取一致快照。适合短提交与后台计算分离，不表示可无限并发写入。见 [SQLite 隔离说明](https://www.sqlite.org/isolation.html)。

SQL 只解决身份映射、参数索引、分页和已记录依赖；语义同指、相反命题识别、动机与因果仍是模型判断。首轮无需图数据库；若实际多跳量测显示瓶颈再替换索引适配器，不改变 canonical 语义。

### 7.2 中文检索

精确名称/别名有独立索引，避免短名字完全依赖通用分词。全文检索可以评估 FTS5 tokenizer 或宿主分词；FTS5 提供 tokenizer 扩展及 trigram 子串检索，但 trigram 对短查询有限制，不能当中文理解保证。见 [FTS5 tokenizer 文档](https://www.sqlite.org/fts5.html#tokenizers)。首轮以人名、别名、双字词、无名称描述分别测召回，必要时确定性子串或分词补充；向量是增强路，不是唯一入口。

### 7.3 版本与缓存成本

不为每个 knowledgeRevision 复制整库。保存不可变增量记录与发布成员关系，物化当前投影；历史查询按 revision 选择，热点范围可缓存。缓存 key 至少包含 manifest、knowledgeRevision、readAt、storyAt/perspective/scope、词项映射与索引版本，不能把全书缓存复用到早期阅读范围。

根 Span 集合与依赖闭包可共享存储并按需计算，避免每条 Fact 内嵌整条证据链。证据展开采用分页；深度/节点数达到上限返回 continuation，不声称所有依据已穷尽。保留历史会持续增长，归档/压缩要另行提出，不以本轮设计授权删除原始证据。

## 8. 并发、中断与重试

### 8.1 单写入者与乐观提交

一个资料库由一个提交协调者串行发布，模型任务可并发读取快照。每个 ChangeSet 带 manifest 与 base revision；提交时用数据库条件检查该 manifest 的兼容 head 与 readSet。初版采用严格 head CAS：head 变化就不直接提交旧结果，先重验/重建变更集；不假设“写不同实体就无冲突”，因为它们可能影响同一个身份或词项。

先计算、后短事务提交，不跨模型调用持有数据库写锁。CAS 失败的输出可复用为候选上下文，但任何变化的材料、身份、反证或范围都必须重新检查。前提没变也需要记录针对新 head 的复核结果；不悄悄把 baseRevision 改成最新。

查询在开始时固定逻辑快照，多页之间不持有长期数据库事务。游标还绑定检索视图：投影 generation、覆盖水位、检索路径、分词/评分版本和稳定排序键；或绑定已保存的有序候选集合 ID。初版结构集合采用稳定 ID/规范排序分页，相关性搜索采用有限候选集快照。后续页不得随后台索引补齐而改变检索视图。该视图/发布 revision 不可恢复或游标不匹配时返回错误和重开提示，不能悄悄切换索引或跳到最新页导致重复/遗漏。

受限扫描尚未遍历 canonical 集合时，保存扫描游标及未完成状态；不能用“不完整”的第一页配上正常的完整索引下一页。当调用者选择使用更新的索引覆盖时启动新查询而非续页。

### 8.2 操作身份和外部调用

operationKey 由任务身份、固定输入、策略版本与显式重跑 nonce 共同决定，唯一发布约束保证同一操作最多提交一次。进程重启后检查已发布标识，而非再次追加记录。新策略或明确重跑创建新操作；语义等价去重仍由知识整理处理，不能仅靠 operationKey。

模型调用持久状态区分 queued、running、responseSaved、validated、committed、failed、cancelled、unknownOutcome。响应保存后可恢复验证而不再调用；请求已发出但响应没持久化时可能已经计费，记 unknownOutcome，不承诺 exactly-once 调用。重新发请求是新 attempt，成本账本保留未知费用；是否重试遵守运行前配置。

取消与发布共享同一个数据库线性化点：取消事务把非 committed 任务标为 cancelled 并推进 executionGeneration；发布事务必须同时检查任务状态、generation 与 head。取消先提交，旧 Worker 即使已 validated 也不得发布；发布先提交，取消返回 alreadyCommitted，不承诺撤销已发布知识。显式重跑或重新领取使用新 generation，迟到旧 Worker 无提交权。

任务取消后迟到响应可以作为审计输出保存，但不得继续发布。模型失败、索引失败、语义候选失败各自记录，不把它们全归为“提取失败”后无限重试。

### 8.3 原文更改与清单版本

每次查询和计算绑定完整 sourceManifest。改写某章会产生新 manifest；已删除或改写内容在旧 manifest 中仍可审计。新 manifest 导入未完成时保留原文就绪状态，旧知识不得无标记混用；原作旧版仍可显式查询。

每个 manifest 有自己的兼容 head 和发布成员关系，Assessment、生命周期与失效水位在该视图求值。M2 原文替换不全局 supersede M1 的命题。显式查询 M1 且省略 knowledgeRevision 时读取 M1 的当前兼容 head；明确提供不属于 M1 的 revision 则报不兼容。旧快照审计与当前纠错后的旧原文阅读因此是两种查询。

共享提取纠错通过反向引用目录找到使用该错误提取 revision 的 manifest：在一个修正发布中登记共享失效根并推进这些 manifest 的 head/失效水位，再异步重评各自派生知识。不直接把 M2 的身份、反证或故事解释复制到 M1。只有相同原文内容及完整提取上下文下的材料纠错可共享；上下文不同的解释分别复核。旧固定 knowledgeRevision 保留原状态供审计。

未改章节的材料可按内容哈希和章节身份复用。依赖原文顺序、相对时间或身份上下文的派生知识还需校验目录与上下文读集；不能因为其直接引用的句子未改就全量复用。相同内容发生在两章或两个事件中仍有不同位置身份。

### 8.4 索引故障

canonical 提交成功、向量构建失败时保留知识，返回向量路不可用；结构查询与原文读取继续工作。FTS/邻接投影版本落后时重建或从 canonical 受限扫描，达到上限报告不完整。索引内容错误不能回写 canonical；从发布 revision 重新生成。

## 9. 宿主与现有包边界

本轮只检查了以下包的 README，不将其宣传性能力当作已验证适配结果：

- [nb-memory](../../../packages/nb-memory/README.md) 的 `facts = happening`、tick 与状态模型和 V7 不同。V7 独立实验，不让旧接口名称决定新语义，不复制其全量注册表进上下文策略。
- [nb-workflow](../../../packages/nb-workflow/README.md) 可组织版本化 Activity，但 Memory Backend 不承担进程重启、多 Worker、租约、持久重试和 outbox。V7 宿主仍需拥有队列与幂等发布，不能因使用 Workflow 就声称有耐久恢复。
- [nb-history](../../../packages/nb-history/README.md) 拥有文件变更与快照历史。可作为原文版本来源的候选，但文件 undo 不等于知识依赖重审；V7 必须单独处理 manifest 变化。正式接入前验证公开接口和事件语义。
- World Engine 负责作者世界模型，Plot 负责创作剧情结构；V7 的 Entity/Episode 不默认为它们的 subject/Scene。跨模块映射需显式外部引用与独立接受流程。

首轮领域内核、存储适配器、检索适配器、模型适配器和宿主调度分离，均可用确定性 fake 驱动修正测试。候选输出不依赖 provider 工具调用协议，未来 MCP 只包装查询能力，不拥有知识真相源。

## 10. 可行性与成本边界

每次处理只召回相关身份与材料；跨章规模通过分区、增量依赖和保存游标控制。首轮不实现任意递归逻辑程序、全时空闭包、全书逐句命题穷举或无界自主 Agent。局部推导链仍允许多跳，查询和重审超限时明确保留未完成状态。

记录每个阶段的输入/输出 token、调用与复核次数、已知/未知成本、耗时、候选命中率、受影响结论数、实际重算数、积压水位和答案材料量。性能试验将冷查询、暖查询、一次身份拆分和一章修订分开，不用一次流畅演示证明规模可行。

SQLite 单机方案是有依据的实施候选；具体数据规模、provider 输出稳定性、中文检索效果、长期依赖规模尚未运行验证。正式运行前选定有限工作量和资源上限；达到上限保留部分进展、覆盖与下一游标，不偷换为成功或无限续跑。
