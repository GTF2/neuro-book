# V7 知识模型

状态与目标以 [提案入口](../novel-memory-v7.md) 为准。本文定义概念合同；可执行的数据结构、字段与约束见 [具体 schema 与查询投影](schema-and-projections.md)，两者共同接受样本金标检验。

## 1. 基本记录与版本

| 记录 | 含义 | 主要连接 |
| --- | --- | --- |
| SourceRevision / Span | 一份原文版本及其中的准确位置 | 作品、章节身份、正文内容哈希、位置 |
| Referent / Mention | 局部指称对象，以及文本中的一次指称出现 | 原文范围、局部对象、称呼 |
| Disclosure | 文本在某个位置由某个来源表达的内容 | 原文、指称、来源、语气 |
| Beat | 章内连续阅读片段及概括 | 原文范围、相关披露与指称 |
| Entity / Resolution | 统一对象入口，以及把指称归给对象的判断 | Referent、实体、具体依据 |
| Fact | 有明确作用域的完整命题 | 带角色的参数、实体或命题引用、时间 |
| Episode | 可跨章的事件或过程组织 | 参与者、步骤、材料、时间、结果 |
| Synthesis | 有覆盖范围的主题、主线或领域综述 | Fact、Episode、材料，逐项依据 |
| EntitySummary | 面向某实体和查询主题的可重建摘要入口 | 实体、阅读边界、视角、条目依据、覆盖与构建水位 |
| Argument / Assessment | 一组支持或质疑理由；给定范围下的当前评估 | 具体版本、前提角色、反证、结论 |
| Watch | 哪类新材料或变化应触发重审 | 对象、关系族、主题范围、未决问题 |

这不是要求为每个表格行创建一张 SQL 表。身份、情节和 Fact 使用共同的论证与版本机制；不同类型的业务不变量仍分别检查。

EntitySummary 具体承接 V4 的“主体介绍”：需要人物背景时先取摘要，再按需展开。Synthesis 仍负责跨实体主题和剧情；两者复用逐条证据与修正机制。摘要不成为新的独立事实根，不能把输入中的自述、条件、猜测或暂定状态抹去。缓存身份与失效规则以 schema 与投影正文为准。

### 1.1 稳定身份与不可变内容

- 系统分配逻辑 ID；LLM 只输出批内引用和输入允许的已知引用。逻辑 ID 不由名字、主谓宾内容哈希或章节展示序号决定。
- 每次修改产生不可变 revision，引用表示为 `recordId + revision`。原文修订、提取纠错、实体重分配及情节重组均显式留痕。
- 逻辑 ID 保留同一记录的纠错历史，不保证其历代内容语义等价。支持旧 revision 的理由不能无检查地支持新 revision。
- 改写成另一个命题、把一个命题拆成两条时分配新逻辑 ID，并保留 replaces/splits 关系。不同记录表达同一命题时由有依据的等价关系整理，不要求文本完全相同。
- 创建新事实不会修改旧材料。当前有效记录通过 `(sourceManifest, knowledgeRevision)` 下的发布成员关系及 supersedes/retracts 决定，不存在跨所有作品版本通用的 active 标志。撤回与后来揭示相反内容不是同一操作；来源版本、共享提取纠错的传播见维护正文第 8.3 节。

### 1.2 原文坐标

每个 Span 包含 sourceRevision、稳定 chapterId、段内位置及必要的字符子区间；展示章号从该作品版本的目录顺序获得。段内区间采用存储正文的 UTF-16 code unit 半开偏移 `[start,end)`，禁止切断代理对；导入器负责测试中文、emoji 和换行。导入时保存精确的规范化正文及其版本/哈希，偏移永远针对这份正文，原始 EPUB/文件的偏移如需支持则另存映射；不能混用字节、UTF-16 与 Unicode code point。重排段落和改变规范化方式生成新 sourceRevision。

段号可以作为显示坐标和初始粗粒度定位，但同一段存在多来源时要能分别绑定子区间。一份正文的内容哈希校验原文，不能代替章节身份或作品版本身份。提及、披露与 Beat 的证据范围都定位于固定版本。

一个记录可有多个非连续 Span；各 Span 指明支持哪个表达部分，不能只给一个巨大范围宣称覆盖全部内容。只有 Beat 强制单章连续区间。

## 2. 指称、实体与身份

### 2.1 为什么保留局部指称

Referent 是一次局部阅读建立的对象锚，如第 8 章“坐到旁边的猫女”；不是每出现一个代词就新建对象，也不等于最终全书 Entity。Mention 保存该处“她”“猫女”等具体用语并指向 Referent。只为进入记忆或消歧所需的提及建记录，不要求逐字标注所有代词。

材料引用 Referent，每个进入记忆的指称论元同时保留对应 Mention 或可重新消歧的准确 Span；不要求标注未进入记忆的所有代词。Resolution 将 Referent 归入一个 Entity，带对应 Argument 和状态。首次出现可以暂建 Entity；查询将候选入口与已确认入口区分显示。名字是有位置和来源的检索标签，不是唯一键。

Entity 只承担持续指称入口。类型、姓名、职业、阵营、身体、所有权均由带依据的 Fact 或名称记录表达，不在实体主行变成无来源的永久属性。

### 2.2 三种不同的关联

| 判断 | 例子 | 行为 |
| --- | --- | --- |
| 同指 | 第 8 章猫女就是第 9 章南嘉鱼 | 可归并查询入口；保留每组材料的 Resolution |
| 身份或角色 | 某人使用一个公开身份、某职业称谓 | 先用带范围的身份 Fact；不能默认把职业类别与个人合并 |
| 不同对象之间的关系 | 意识居于身体、原主人拥有身体 | 分别建对象并连 Fact；外貌相同不证明同一个人 |

人物、组织、地点、道具、类别、抽象制度都可成为 Entity，但对象与类别不可因同名合并。“魔法少女”这个类别可有规则与成员；其规则不会无条件复制到每个成员。书中虚构、传说或假身份也可有检索入口，存在状态由带 scope 的命题表达。

### 2.3 合并与拆分

归并发布改变的是一组 Resolution 和当前代表入口，不破坏局部对象与材料引用。明确同指的多个旧入口可重定向到一个代表入口；重定向版本化，旧 ID 仍可查询历史。暂定同指不进入默认确定性归并。

拆分时必须给出：受影响 Referent 集合、各自新的归属或 unresolved、应撤回的身份理由，以及受影响依赖。不能只创建第二个 Entity 后把旧事实全复制过去。

局部 Referent 自身也可能错误地合在一起。允许一个 Referent 拆成多个新 Referent，版本化重分配 Mention/论元 Span，并重新提取受影响材料；旧 Referent 保留 splits 关系。同一个“她”被错用于两个人时按具体论元定位重解，不仅改变整个 Referent 的全局归属。缺少精确定位的材料整条进入重审。

归一化 Fact、Episode 参与者及名称索引记录使用过哪些 Resolution revision。一次事实若同时依赖两组待拆材料，应重新解析整个命题，不能按字符串替换主语。依赖无法细分时整条降为待重审；这是保守代价，不编造精确归属。

身份可能随故事变化，例如组织改名、改组、两个意识融合。名称变化通常不是对象替换；持续身份是否成立由文本及解释决定。`sameReferent` 等价仅限同一作用域下无条件同指；“曾融合”“扮演”“转世关系”用有时间的 Fact 表示，不套全局等价传递。

### 2.4 对象延续、名称使用与名称真实性

“眼前的黑色古书继续说话”支持持续追踪同一对象；“它自称墨丘利秘典”支持将这个名称作为来源可追溯的称呼。两者都不自动证明该对象确实具有名称所暗示的来历、资格或身份。名称不能充当未经评估的世界身份断言。

名称投影携带自己的原文/提及与归属依据。撤回名称依据时，当前显示回退到仍有依据的称呼或中性对象标识，不删除持续对象；撤回同指依据则重新评估受影响材料归属。首次称呼也没有绕过证据检查的特权。依赖名称的界面检索不得从原始快照最终 label 绕回已失效或未来名称。具体快照支持的范围及校验以 schema 与投影正文为准。

## 3. 披露与 Beat

Disclosure 保存文本表达，最低包括：完整释义、一个或多个证据 Span、来源通道、说话者或意识持有者、语气、涉及的局部对象及必要的所述时间。问句、请求、承诺、计划、猜测、否定、条件不能在释义中丢失。

来源通道采用 narrator、author/parataxt、in-world-system、speech、thought、document 等少量类别，必要时扩展。通道与 attribution 分开：叙述者可以报告角色内心；一封信有作者、被引用者和读取者。报告嵌套保留链条，无法解析的部分标 unknown 并保留原文，不平铺成多个独立目击证人。

一条披露以可独立引用的表达单元为尺度；不同来源或语气可拆分。对一个长条件句不能为了原子化拆掉条件。角色台词记录“说了 P”，不自动得出“相信 P”或“P 成立”。系统通知也只是书内来源，不能当现实宿主指令。

Beat 负责阅读检索和局部概括：

- 同一章节当前切分版本的 Beat 连续、无重叠地覆盖全部原文，标题、副文本也有归属。
- Beat 可承载动作、描写、说明，不要求是一个世界事件。一个 Episode 可关联多个 Beat；同一个 Beat 可贡献多个 Episode。
- gist 的全部信息必须被所声明材料支持；引用前后文帮助解释时，该上下文必须显式进入其依赖和可见性边界。不能把后文名称悄悄写入早期 gist。
- 披露与 Beat 都可以直接用于回答或作为推断前提。它们都是提取产物，其释义正确性与范围可能被后续审查撤回。

## 4. Fact 的命题内容

### 4.1 最小逻辑形状

```text
Fact revision
  proposition: 完整自然语言命题
  predicate: 关系或属性语义的版本引用，或 unresolved 词项
  arguments: [{role, value}]
  polarity: affirmative | negative
  scope: 作品/叙事世界 + 命题模态与归属
  time: 故事时点/区间/约束引用，或 unspecified
  qualifiers: 必要条件、数量限定、方面、单位、适用对象
  interpretationDependencies: 使用过的身份/词项/时间解析版本
```

值可以是实体或 Referent 引用、命题引用、Episode 引用、带单位数字、文本或明确的 unknown/none 表述。字段缺失仅表示未记录；文本明确说“不知道死因”应记为一个带持有者和来源的命题，不能用 SQL null 代替。对象未消歧的 Fact 可以保存和检索，但不以确定实体关系进入默认图。

Fact 以一个可独立支持、反驳或限定的命题为粒度。同一来源“有两只尖耳”通常分为数量和形态两个 Fact，共享原文依据；只确认数量的另一来源不支持“尖”。条件或量词不可分割的命题保持整体，不强制转换为普通三元组。

### 4.2 谓词与有限结构化

PredicateTerm 包含稳定语义、参数角色、方向、值域描述、对称性及冲突比较提示。核心只覆盖同指、类别成员、命名、关系、部分、属性、时间和认知等通用机制；书内关系与规则允许扩展。

“朋友”“挚友”“暂时合作”不是默认同义词。词项归一化和宽窄关系需要理由与版本；检索可以扩展候选，精确集合结果只有显式等价映射才合并。一个词项可有多个含义，按上下文消歧。无可用词项时保留命题与候选词，不因缺少本体丢内容。

词项等价与类别包含是不同关系。类别包含用带依据的 Fact 表达，例如“本书语境中的公会是组织的一类”；accepted 的无条件类别包含允许成员沿上位类别传递，不把两种类别 ID 合并。默认类别集合查询包括直接成员及经适用的 accepted 类别链可推出的成员；每个派生成员携带完整分类依据。该有限闭包可在查询时确定性生成，不需每次调用模型或先永久物化所有成员 Fact。

类别链有条件时必须绑定并满足条件；未决的成员或包含关系进入集合的 ambiguous 组，不计入确定成员。对 accepted 无条件类别链做闭包前检查循环：显式等价可规范为同类，未经证实的互相包含作为待审分类，不能靠环获得成员。深度/节点上限导致未展开时返回 incomplete，不能声称 recordsExhausted。类别成员传递不意味着类别的所有属性或通常规则向实例继承。

图上的语义边由 Fact 投影：边带 factId、参数角色和 Assessment；about 仍只表示相关。双向朋友关系可以展示两端邻接，但底层仍是一条命题和同一证据，不创造两份支持。

不把“超过二元就是情节”作为规则。例如 A 向 B 借 C 有事件身份，但“在制度 D 下 A 对 B 承担义务 C”仍可能是一条语义规则。需要独立追踪的发生过程进入 Episode，必要的关系角色保留在 Fact 中。

### 4.3 规则、条件与类型

力量和世界规则允许一般命题，显式保存量词（全部、通常、存在、未知）、条件、效果、代价、例外和模态。有限结构能表达时使用命题引用与角色变量；结构不能表达的部分保留完整文本并标 `textualCondition`，查询不能假装执行了它。

例如合成规则“只有持有通行证的成员才可进入”不等于“持有通行证即可进入”。规则方向必须显式；只有、除非、可能、通常等不得被擦除。规范“禁止进入”也不等于事件“不曾进入”。类别提供检索入口，不自动提供成员的实例属性。

只自动执行显式定义且适用条件已满足的有限规则；复杂归纳、例外判断与常识推理由整理模型提出独立 Argument。推断引入的假设必须列出，不能冒充原作设定。与原文无关的常识可以用于生成搜索问题，不能独立成为 accepted 原作 Fact 的证据根。

### 4.4 作用域与角色认知

命题区分故事世界陈述、某来源的说法/信念、假设分支、书中梦境/传说/虚构故事。书中角色做的梦与系统的“梦境整理阶段”无关。

“A 声称 P”可以可靠地被记录，即使 P 本身错误；它不能无条件支持世界 scope 下的 P。若整理器据台词接受 P，必须新增从角色说法到世界判断的 Argument，说明为何采信，保留反证。叙述者同样是来源，但普通明确叙述可以用直接文本支持形成世界 scope 命题，不需要先伪造“全知叙述者”实体。

认知采用指向命题的关系，例如 A 听闻/相信/怀疑/知道 P；事件听者不自动全都知道台词内容。知道 P 至少需要认知依据；文本只说明听到时先记听闻，不能推成理解、相信或记住。`knows(P)` 作为角色认知报告不用于反向证明 P；当 P 的世界判断被反驳时重审其“知道”措辞，保留原来的报告。

未记录知道，不等于不知道。负面认知需明确证据；人物在分叉时的资料返回已支持、可能和未知，不能生成完整心理状态快照。

认知与引语的内嵌命题是身份替换受限的边界。保留持有者使用的 Referent、称呼或身份呈现方式；全书 Entity 映射只提供导航，不能改写该命题的认知含义。例如甲相信“蒙面人救了我”，并相信“乙没有救我”；即使全书已确认蒙面人就是乙，也不能据此报告甲相信“乙救了我”或直接判甲自相矛盾。只有甲在所查询时点知道两者同指的独立依据，才允许在其认知范围替换。该限制同样适用于假身份、转述和角色以错误名字认识他人；世界层的 Resolution 无法替代角色自己的身份认识。

### 4.5 浏览投影与命题完整性

主体概览只提供对象导航。把同一主体对的多条命题分组显示，不表示这些命题属于同一种关系、同一时点或同一来源；分组必须可逐项展开完整命题、断言类别与评估。连线方向不从论元数组次序猜测。

命题视图保留 Fact 的独立身份，单主体属性、多元关系和没有实体论元的命题都能选中。参数引用用于解释命题中的角色，不把任意两个共同参与者自动解释为二元关系。局部图可以限制可见范围，但需与完整的范围内命题目录相连，并说明显示范围；世界断言和角色信念不能因具有同样的实体端点而合成一个世界事实。读者看到的断言类别回答“在说哪一种内容”，Assessment 回答“目前如何评价它”，两者分别呈现。

主体图可以由显式 KnowledgeAccess 提供认知导航：从持有者连接到目标命题直接引用的主体，保留听闻、读到、相信、知晓的模式以及知情记录和命题引用。同一有向主体对可以聚合显示，但每项依据仍独立可查。“相信相关命题”不等于相信该主体，“听闻相关说法”也不证明该主体存在或身份真实。未察觉不投影为正向认知连接，缺少知情记录不能解释为不知情；不沿读者的身份归属链替换角色所用的局部指称。阅读边界、失效状态和命题筛选同时约束这些连接。

记录溯源与故事关系是两种表示。提及、局部指称、身份判断和主体即使同名，也须以类型标签和不同视觉标记区分；默认显示与所选记录相关的解释链，完整依赖另行展开。原文出现位置用于回答“哪里提到这个对象”，记录来源及依赖用于回答“这条判断根据什么成立”，两种入口不能混成一个无类型列表。

## 5. 情节与综述

### 5.1 Episode

Episode 是整理后的事件或过程：标题、完整简述、尺度、带角色的参与者、所属叙事世界、材料引用、步骤关系、时间约束、结果及相关 Fact。它可跨章、非连续、有多个叙述版本；不是原文切块，也不要求对应产品 Plot 的 Scene。

简单事件可直接关联材料；较大的过程包含 Episode 子项，`partOf` 必须无环，可多父，例如同一救援同时属于人物成长线和势力冲突线。组装时保留共享子项身份，不复制成两次发生。

步骤关系分 before、continues、retells、motivates、causes、enables 等。叙述顺序从原文位置取得，故事先后和因果是各自有依据的关系判断；同一故事事件被后文回述不新增发生次数。不能仅因顺序相邻就生成因果。

相识、关系发展、章节概括并非同一尺度。首次相识 Episode 可以在互报姓名结束；后续吃饭是另一事件，与前者同属关系发展过程。边界可修订；查询应能取得当前聚合依据与原始局部材料。

Episode 的标题、参与者、步骤、结果分别能定位支持它们的材料。一个结果被反驳不应抹掉已发生的整个过程；依赖粒度至少到这些组件。释义整体无法拆分时整版暂缓，而不是保留误导性半句话。

### 5.2 Synthesis

为世界观、力量体系、人物发展、冲突主线和全书主题保留可查询综述。它有明确的覆盖章节/主题范围、事实与情节条目、每条判断的依据、未覆盖部分及生成版本。

综述可由局部综述逐层组织，聚合图无环；上层仍能展开到原始 Fact/情节，底层变化触发受影响条目重审。不能只反复改写上一版摘要，因为那会让被压掉的细节永远失去机会。周期回访材料用于检查遗漏。

“主题”通常属于系统解释，不能转写成“作者意图已证实”。当前成熟主线、次线、伏笔候选分别标示，支持千字摘要时提供重要性选择及依据，由 Agent 决定最终篇幅。综述可作为推断线索；作为论证前提时必须引用具体条目及其依据，不能把整篇流畅文字当一份独立证据。

## 6. 时间与阅读范围

### 6.1 四个独立概念

| 概念 | 含义 |
| --- | --- |
| 文本位置 | 一个作品版本内的章节顺序与原文位置，确定可比较 |
| 故事时间 | 文本表达或推断的发生/成立时间，可能只知道局部先后 |
| 知识 revision | 系统在哪次发布形成当前认识，用于一致性、审计和修正 |
| 角色认知 | 某角色在故事时点的认知命题，不从阅读位置自动推得 |

时间引用可表示点、区间或未知，不要求绝对秒数。相对词必须保留锚点及来源；两个“三年前”不因文字相同而合并。“在 t 时是朋友”是观测，不等于“从 t 开始是朋友”。

可推得 before/after/during/overlap/equal 时存带依据的判断；约束矛盾标 disputed，不靠任意删除一条边造出总时间线。同一粗粒度场景中可根据连续动作推导局部先后，但不得把所有同 Moment 的后一句自动覆盖前一句，回述和引语仍可能指过去。

### 6.2 持续、变化与冲突

相同主体、谓词、作用域、兼容故事时间和条件下互斥的命题才形成冲突候选。不同时间的所在地可接续；不同持有者的看法通常是并存；尾巴的触感和外观不是竞争。

文本明示端点时保存端点；只有观测时保存观测。状态持续可以成为独立推断，记录从哪次观测向哪里延伸、采用何种持久假设、为何无已知终止信息。它不制造真实端点；以后读到变化或发现时间不适用就重审。

无新材料不让知识自动 TTL 失效；易变度用于重审优先级，不承担真值判断。反复被引用、出场频繁、叙事重要都不能替代证据。

### 6.3 历史阅读范围

指定 readAt 时，只有其证据与解释前提在该位置可用的结果才能展示。名字、身份归并、否定、反证和因果解释都参与过滤，不只检查最终 Fact 的创建位置。

一条结论有多个 Argument 时，只要至少一个在范围内可独立支持该结论，就可按该范围评估；不能把所有依据的最大位置当唯一门槛而误隐藏早已可得的结论。全书视图中的反驳若在未来，不能使早期可见说法消失；需对所选可见依据重新评估。

材料提取纠错属于知识 revision，不是故事揭晓：纠正“把问句提取成断言”会修正当前系统对所有 readAt 的提取解释；历史 knowledgeRevision 仍能审计旧错误。新章否定旧话则保留旧话，在更晚 readAt 显示反证。

后文模型看过秘密后产生的早期解释不能仅靠删掉引用来取得早期可见性。用于有限 readAt 的新解释，必须通过只提供可见材料、身份和词项的范围内复核；未复核时只返回早期材料与当时已发布解释，或标该范围整理未就绪。

## 7. 依据、推断与评估

### 7.1 Argument

一条 Argument 支持或质疑一个结论组件，包括：目标 revision、方向、方式、精确前提列表、各前提的作用、必要假设、简短推理理由、所使用身份/时间/词项版本、执行来源，以及适用范围。

规则应用还保存变量绑定与联合适用环境：每个变量绑定的实体/身份呈现、各前提的事件或时间变量、共同 scope、条件约束和结论所述时间。程序可表达的变量必须一致，所有必要条件必须能联合满足；不能把甲的成员身份与乙的通行证拼给一个变量。需要同时成立的状态必须有支持其共同成立时段的依据；两段时间确定不相交则该规则应用不支持结论，无法确定交集则至多 conditional。步骤先后型规则可以使用不同时间变量，但其先后/同一互动约束也必须有依据，不能机械要求所有事件同时发生。

前提中的未消除条件传到结论或令其 tentative；不能将“若下雨 P”当成无条件 P。仅有 textualCondition 而无法核实是否满足时不做确定性规则执行。语义推断可以另提论证，但同样要解释共同适用范围和未决条件。

同一 Argument 内前提是共同必要的 AND；多个独立 Argument 是替代支持路径 OR。支持与反对分别记录，不能因为正向数量多就忽略反例。质疑可指向命题或某条 Argument 的有效性；推断规则误用与命题为假不同。

直接原文依据合法，不要求原文必须先变成 Disclosure。Disclosure、Beat、Fact、Episode 组件及 Synthesis 条目均可作为前提，但只有当前适用 revision 和评估状态允许其以对应强度使用。

初版推断的必要知识前提若 tentative/disputed/unsupported，输出至多 tentative；stale/pending 的前提不进入新的 accepted 推导。若存在另一条完全独立且合格的 Argument，可按该路径重新接受结论。直接材料前提先核对其提取有效性；纯原文 Span 也必须经过本次语义支持检查，不因坐标合法而自动 accepted。该保守规则不实现不确定概率演算或任意反证法。

### 7.2 证据根、相关性与循环

原文是证据根，系统重复解释不新增根。若同一原文提取出三个 Fact，再分别支持第四条，不算三份独立来源。保存原始 Span 集合和已知转述链；不同段落不保证来源独立，无法判断时标“独立性未知”。根集合用于去重与审计，不当概率计算公式。

每个 accepted 结论必须存在有限、可展开到原文的有效支持路径。系统假设可以参与候选推断，但纯常识、模型自述或无来源的循环不使其成为原作知识。

同一发布图中支持依赖按逻辑结论身份检查无环，不能通过引用旧 revision 绕过 A 支持 B、B 又支持 A。更新自己的理解时旧结论可作为检索上下文，不作为自我支持前提；从具体材料或独立前提出发创建新 Argument。存在外部支持的互相解释保留其中非循环支持路径，其余关系可作关联，不作支持边。

Episode 包含 Fact 时不能再用这个完整 Episode 支持同一 Fact；可选引用其中独立材料组件。身份判定也不得以已假定该身份才能成立的归一化 Fact 为唯一依据。

### 7.3 生命周期和认识状态分开

| 轴 | 值与意义 |
| --- | --- |
| 记录生命周期 | active、superseded、retracted：此版本是否仍是当前材料/解释 |
| 整理状态 | ready、stale、pending：依赖是否已针对当前版本核对 |
| 认识评估 | accepted、tentative、disputed、unsupported：在所选作用域与可见材料下如何使用 |

`accepted` 表示满足发布策略的有依据认识，不等于绝对真理；tentative 是有理由但关键假设未稳；disputed 有未解决的实质冲突；unsupported 当前没有合格支持。提出相反命题不能自动把旧命题标为 false，反证也需要评估。

Assessment 返回结论、上述状态、支持/反对摘要、未决假设和依据入口。角色说法可以在 attribution scope 下 accepted，而世界 scope 下对应命题仍 tentative。

默认知识答案使用 ready 的 accepted 项，并同时携带相关 disputed/tentative 提示；不把不确定项偷偷排除后假装已解决。纯材料检索可返回尚未归一化材料，但明确标记。缺乏结构化知识时 Agent 可直接使用披露、Beat 或原文。

#### Argument 的可用状态

在选定 manifest、knowledgeRevision、readAt、故事范围及 perspective 下，先过滤来源与前提，再按依赖无环顺序求值。语义复核负责产生有依据的支持、冲突和缺陷判断；查询按以下规则确定性汇总，不调用模型临场裁定：

| 状态 | 条件 | 对结论的影响 |
| --- | --- | --- |
| usable | 必要前提 ready/accepted，直接材料有效，绑定/范围/条件成立，语义复核通过，无未决有效质疑 | 可以形成 accepted 的支持路径 |
| conditional | 有有效材料，但必要前提 tentative/disputed、存在未消除假设或联合适用性不明 | 至多形成 tentative 支持；保留条件 |
| challenged | 对该 Argument 存在已复核为有根据但未解决的有效性质疑 | 不作为 accepted 路径；与其他独立路径分别计算 |
| blocked | 版本/水位待重审、前提 unsupported、共同条件不可能、范围不可见或已确认推理无效 | 不提供当前支持；区分待重审与已否决原因 |

质疑一个 Argument 并不等于证明其结论为假。对命题的反对 Argument 经同样规则求值；纯无依据的怀疑不自动制造争议。反证要被排除，必须有可审查的失配/撤回/无效判断，例如针对不同时间、来源已撤回、把必要条件错作充分条件；“新来源更晚”或“正向票数更多”不构成排除理由。对质疑的再质疑若形成评估循环，相关部分保留 challenged/disputed，不能靠循环互相恢复 usable。

#### Assessment 的确定性汇总

| 可见、适用的论证情况 | 认识状态 |
| --- | --- |
| 至少一条 usable 支持，且无 usable/conditional 的实质命题反证 | accepted；不相关候选不影响该结论 |
| 正向有 usable/conditional 支持，反向也有 usable/conditional 实质支持 | disputed，直到有依据解决相容性或排除某方 |
| 没有 usable 支持，但有 conditional 或尚未解决有效性质疑的正向理由；无上述双向冲突 | tentative |
| 没有合格正向理由，包括只有反向支持或正向理由全被否决 | unsupported；不自动创建另一条否定 Fact |

stale/pending 是更外层的可用性限制：即使缓存认识状态为 accepted，也不能跳过维护正文第 3.4 节保护而返回当前 accepted。被挑战的一条支持不污染完全独立的 usable 支持；命题层反证影响所有支持路径。普通 readAt 过滤会重新选择路径；某范围缺乏所需复核时返回 pending，不复用全书评估标签。

### 7.4 从候选到可用认识

所有模型输出先是候选。程序验证形状、引用、版本、范围和无环；语义复核验证证据是否支持命题、身份是否合理、条件来源有没有丢失。原始输出和复核结果分开保存。

清楚的直接表达经局部证据检查可 accepted；跨章推断须有独立于生成步骤的证据复核，通过后也可 accepted，不要求人类逐条批准。身份合并/拆分、否定旧认识、规则泛化、世界 scope 的动机/认知推断必须进入该复核路径。复核失败或证据不足留 tentative/disputed 并继续查询可用材料。

“独立”指隔离生成结论的说服性上下文，复核收到命题和依据自行判断；可以用同一模型，不能把模型赞同当正确性的证明。真正质量仍由场景与人工材料对照检验。具体自动接受阈值不使用未经校准的百分比；初版按上述类别与必要证据条件执行。
