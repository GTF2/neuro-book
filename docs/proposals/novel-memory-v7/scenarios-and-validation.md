### 2.2 读完第 9 章

朋友 Fact 的示意：

```text
F_friends_v1
  proposition: 苏天晴与南嘉鱼在课堂交友互动后成为朋友
  predicate: friend-with（双方角色明确，对称）
  arguments: 苏天晴 / 南嘉鱼
  scope: 原作世界
  time: 交友互动完成时的观测；不宣称永久有效

A_friends_v1
  supports: F_friends_v1
  premises: 第9章3段交友请求、8–11段应答与加好友
  interpretationDependencies: 两位参与者的具体 Resolution revision
  rationale: 请求获得回应并有加好友行为，支持建立朋友关系
  doesNotEstablish: 深厚友谊、信任、恋爱、知晓秘密身份
```

这是可被系统接受的关系解释，不要求原文恰好出现一句“二人从此成为朋友”。若语义复核发现应答不充分，保留 tentative 并返回互动材料，不能自动补强；验收要求系统能在这些真实材料上形成有依据的可用关系，而非永远停在候选逃避任务。

## 3. 修正的完整推演

### 3.0 多前提与集合的正向、反向验证

**真实相识材料的联合绑定。** 第 9 章纸条请求与应答必须绑定到同一次交互、同一请求者和回应者。两个动作依序发生，不要求时间交集；论证必须证明应答是在回应这张纸条。若另一场景里另一个人也说“当然”，不能因文字相似把它用来支持这次交友。第 2.2 节的朋友 Fact 因此属于有明确参与者与步骤约束的语义推断，不是一条“请求后任何肯定词都成立”的通用逻辑规则。

**合成权限规则。** 原文明示“成员持有通行证时可以进入馆内”。规则和“甲是成员”“甲持证”都有直接支持，绑定变量 x=甲、同一馆和同一故事世界；两项状态在 t3 有共同成立的依据时，推出甲在 t3 有进入资格，查询返回资格及三项依据，不能推出甲已经进入。若新材料明确甲在 t2 退会，而通行证 t4 才取得，先触发重审：旧 t3 依据尚未排除时保留 disputed，不能让后文自动获胜。只有复核确认旧 t3 提取误读、撤回其支持并接受新的时间约束后，才因两项时间不重叠否决旧 Argument。若从始至终只知两个观测点而无法知道是否重叠，则至多 tentative。若持证对象其实是乙，变量绑定失败。这是验证有限规则机制的虚构输入，不是样书设定。

**合成上位集合。** 甲会属于公会，乙团属于骑士团，丙会分类不明；原文与整理依据支持公会、骑士团均属于本书“势力”类别。查询势力默认返回甲会和乙团及各自分类链，丙会进入 ambiguous；不需模型临场重读所有组织描述。甲会另有直接势力标签时仍只计一次。骑士团包含关系被反证后乙团移到争议项，集合响应更新；原文未明确“只有这两家”时不宣称全书封闭。

### 3.1 合成误合并

为验证机制，另造一个与真实样书无关的同名角色乙。材料 `M_a` 属于甲，`M_b` 属于乙；先故意让两者归到 E，同一个朋友 Fact 错误地连到乙的组织。

发现误合并后：

1. 新 ChangeSet 引用当前 head，声明 `M_b` 对应的 Referent 改归 E_b，并撤回错误 Resolution 的支持。
2. 发布失效根；旧关系、相关 Episode 参与者和综述不能继续以当前 accepted 返回。
3. 重审时使用各自的局部材料，生成正确归属。横跨两者的错误合取整条重提取，不复制到两人。
4. 若朋友 Fact 有不依赖错误归并的独立支持路径，可重评后继续可用；组织关系若只靠误归并则 unsupported。
5. 旧 knowledgeRevision 仍可审计错误版本，最新查询按新身份返回。

成功条件：不仅人物节点数改变，下游错误关系和派生答案也随之改变；无关人物知识仍可查询。

### 3.2 合成局部指代错误

两处“她”在 ingest 中被错归一个 Referent，但实际属于两人。按 Mention/论元 Span 拆分该 Referent，重新提取“递刀”和“逃跑”材料；无法定位的材料降为 pending。成功条件是两次行动分别回到正确参与者，不要求全书每个代词都建节点。

### 3.3 真实材料上的提取纠错

V6 首 Beat 的“手足无措”超出证据范围。V7 导入它只能作为旧提取候选。两种合法修正：收窄 gist 到 1–3 段实际内容，或重新切分相邻 Beat 并调整共同边界，确保一章覆盖仍连续且不重叠。只把 visibleAt 改到第 4 段却不声明支持材料不是完整修复。

任何依赖错误 gist 的推断都必须重审；依赖原文第 4 段的独立论证不因这个 Beat 错误自动失效。

| E05 | 两个整理任务基于同 head | 一个提交后另一个必须重验，避免覆盖新反证 |
| E06 | 某章改写、删除或章节重排 | 新 manifest，旧位置不冒充新版；相对时间依赖重审 |
| E07 | 向量服务失败 | 已发布知识和确定性读取仍可用，标向量路不可用 |
| E08 | 依赖闭包检查超过上限 | 返回 pending/stale 或截断，不当作验证通过 |

## 5. 八类问题的验收映射

八个原始问题逐字保存在需求基线，本表只写验证目标。

| 需求编号 | 验证对象 | 合格证据 |
| --- | --- | --- |
| 1 整体认识 | 故事前提、核心人物、冲突、主线综述 | 关键判断有材料支持，次要细节不挤掉主要冲突；仅 20 章时明确范围 |
| 2 千字剧情 | 跨章 Episode 与主线压缩 | 保持关键先后、转折和因果归属；字数由 Agent 控制，不能靠全量节点堆砌 |
| 3 关系网 | 身份归一与关系 Fact | 同一人物统一入口，关系有方向/含义/依据，未将共现升级 |
| 4 世界观 | 分类、组织、环境及规则综述 | 散落材料能汇集，原作设定与角色说法/系统解释可区分 |
| 5 力量体系 | 来源、获取、成长、代价、限制与例外 | 不把条件倒置或常识补成设定；缺失明确标注 |
| 6 势力集合 | 实体类型与成员/关联分页 | 当前记录可完整遍历；集合范围和歧义透明，不用 top-k 冒充全部 |
| 7 相识过程 | 8–9 章 Episode | 返回连续过程和参与者动机来源，回述不重复发生 |
| 8 if 资料 | 全书证据下的分叉查询 | 既有背景、当时认知、原作未来、无法定位信息分开 |

语义和情节两类查询必须同时达到基本可用性，不能用关系网通过抵消剧情查询失败。结构解析成功、实体数量减少或图更漂亮均不是问答质量验收。

## 6. 实验方法与判定

### 6.1 分两层验证

确定性层使用手工小记录和 fake 模型：验证 revision、依赖、无环、CAS、取消、恢复、范围与分页。语义层使用真实小说抽取和查询：核对身份、来源、命题、关系、情节、召回与答案。前者通过不证明后者通过。

先验证一个闭环：形成朋友 Fact 与相识 Episode，查询两类答案，注入局部误指代或提取纠错，再查询观察变化。闭环通过后扩展到二十章、八类问题和至少一组未用于调整提示词的材料。全书能力需更长文本和不同叙事结构的独立样本，不从样书第一章外推。

真实材料问题预先写下关键答案要点、允许解释及禁止断言，并给每项的原文依据。人工核对评测，模型辅助评审只作问题发现；用户个人对“重点”的取舍单独记录，不伪装成客观唯一金标。

### 6.2 必须分开报告的指标

| 指标 | 分母与解释 |
| --- | --- |
| 命题依据准确性 | 抽查返回的命题条目中，支持范围/条件/来源正确的比例；报告样本数 |
| 核心信息召回 | 预先标记的关键要点中被正确取得的比例；不以抽取总条数作分母 |
| 身份正确性 | 经人工标记的同指/不同指案例分别统计误合并与漏合并 |
| 情节正确性 | 标记的步骤、事件身份、先后、因果分别统计，不把任一顺序边当因果命中 |
| 修正完整性 | 注入变更后应失效的依赖中实际处理比例，同时记录误伤无关记录 |
| 覆盖诚实性 | 截断、未处理、未定位、争议是否在响应中准确揭示 |
| 查询负担 | 每题工具轮次、返回 token、原文展开次数与错误恢复次数 |
| 运行成本 | ingest、增量整理、梦境、复核、查询各自调用、token、耗时、已知/未知费用 |

不在没有基线时宣称 95% 准确或固定成本。首轮进入扩大实验的最低门槛：上述闭环场景无已知身份错配、来源升级、时间回填或 stale 结果误报；矩阵的确定性不变量全部通过；八类问题均给出可审查输出和缺口。整体语义质量及成本是否可接受由开发者基于结果审查，不用随意数值替其决定。

有限范围的前二十章问答可以失败并暴露缺口，但不能将明显错误隐藏成“待后续优化”后宣称完成。不能把全量问题要求缩成只需 top-k 命中，也不能只用一次查询 Agent 的答案来证明建图系统已经整理了相应知识。

## 7. 实施顺序建议与停止点

1. 将接受的模型转为 planned Spec；实现版本记录、论证、范围和修正的最小确定性内核。
2. 手工装填贯穿样例及反例，验证两类查询和一次修正；不先连接付费模型。
3. 接入受限材料提取和增量整理，真实处理样例，比较手工预期与实际结果。
4. 增加梦境任务、主线综述和八类问题，量测二十章整理/查询成本与错漏。
5. 用未见材料验证更长文本、非线性叙事及失败恢复，再决定产品集成。

这些是设计中的验证顺序，不是已授权实现任务链。本轮没有编写 V7 schema、运行测试数据、真实模型调用或创建产品迁移；文档审查结论保存在 [Task 复核记录](../../../.agents/works/w00005-novel-understanding-spike/tasks/t06-v7-model-design/walkthroughs/design-review.md)。
