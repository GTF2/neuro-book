2. **六类待办枚举全定义**（蓝图 :101 分类×展现矩阵）：①工具审批 ②设定拍板 ③伏笔未还 ④Workflow 应答 ⑤正文变更审 ⑥计划确认。G1 施工覆盖已有实源的四类（①②④+伏笔③的计数行）；⑤⑥只定义枚举与路由常量占位（⑤界面归 G2/G3 融合审稿，⑥路由已拍板=堆叠卡一族）。

4. **持久化语义**（断头路 A9）：①中断/重进后待办全在（驾驶舱可重新唤起）②半处理队列恢复为剩余未处理件（已划掉的不复活、未处理的不丢失）。两条断言必落。
5. **统一应答协议**（与选择题 1B 同轮定）：阻塞型（AgentUserInputPrompt）与后台型（Workflow PendingAsk）在协议层统一表达（同一 pending 项结构：kind/发起源/载荷/应答回传通道），UI 层保留「阻塞卡在输入框上方 vs 后台行在面板」的舞台分工（登记不施工节职能不互替原则继续生效）。**红框条目归位**随协议落地：AgentUserInputPrompt 阻塞卡的入口位置按统一应答协议归位，挂载点以现行代码为准（AgentComposer.vue:539，BOARD 旧登记 :574 已漂移）。
6. **K4 影响项 ID 化**：影响项与提案绑定生成（结构化 ID），拒绝=整组影响项同步销号不留幽灵（断头路 A4）；影响分析产出直接生成驾驶舱待办行，销号走对应待办闭环（断头路 B3，与 A4 对称）。
7. **K5 计划修订回传协议**（断头路 A12）：修订以结构化 diff+文字回传，AI 应答「认可/冲突」一次即开工（不无限往返）；计划连同用户改动入档可溯。request_user_input 的 form 类型已在，diff 协议在其上扩展。
8. **K1 灵感库（用户拍板：做）**：未选项（选择题未选分支/被拒提案的可用残料）自动入库可回捡，新数据结构随待办库同轮落库；回捡入口=驾驶舱待办行（形态细节可后补，数据层必须本轮落）。
9. **K2 置信度（用户拍板：协议扩展）**：writer 输出加 confidence 字段；低置信自动变选择题（接 request_user_input question 类型）；解析对无字段的旧输出必须向后兼容（缺省=不标注，不得报错）。
