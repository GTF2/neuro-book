## 契约基线（前线定，执行中偏差必须披露并给理由；复核方可增删）

1. **块级 diff 数据结构（G3）**：`ReviewBlock{blockId, sourceId, old, new, status, impactIds}`——status 枚举=`pending/accepted/rejected/void`（施工计划 P0-02 明文）。blockId 全局唯一且不复用（旧组 void 后重新提案=新组新 ID，防幽灵）；**void 组的 ID 与决议记录不物理删除**（保留可溯，防历史断链——参谋部复核裁定）。
2. **状态机**：`pending→accepted`（触发正文写入）；`pending→rejected`（转引用气泡+重新提案通道）；整件拒绝=全组 `void`（终态，不可复活，与 K4 整组销号对称）。void/rejected 块不得再次迁移。
3. **块↔正文映射**：blockId 与章节文件行段的映射结构**挂 nb-history 快照体系扩展**（架构对账 G3 建议落点），**禁另起第二套历史/快照系统**。
4. **写入与撤销通道**：通过块立即写正文=`WorkspaceHistory.performWrite/registerWrite`（时间线自动可溯）；撤销=`revertAtRevision`（乐观锁，防并发覆盖）——撤销/恢复验收的底座，不自写回滚。
5. **对照视图底座**：diff 计算用 `WorkspaceHistory.textDiff(beforeHash, afterHash)`（现成，底层 diffLines），禁复制另一套 diff 实现；审稿窄栏展示的块级 old/new 从 textDiff 结果切块派生。
6. **与 G1 统一待办库对接**：`UnifiedTodoKind` 的 `content_review`（G1 占位）接实——审稿件入统一库、计数读库（A8 延续）、**拒绝块转堆叠卡待办**（断头路 A10：拒绝防丢）。
7. **拒绝闭环**（蓝图 :99）：rejected 块变引用气泡挂输入框上方，用户带引用写修改意见发送→AI 重新提案（新 ReviewBlock 组）；旧组 void 保留可溯。
8. **决议记录归档**：逐块决议（通过/拒绝/整件）归档可溯（断头路 A10③）——载体=nb-history 操作日志侧记录（写入原因/决议引用），验收锁「任一块的终态可回答谁在何时因何通过/拒绝」。
9. **审稿视图准入**：仅涉正文实质改动件进审稿视图（蓝图 :101⑤ 用户定）；轻量快批件（工具审批/设定拍板/Workflow 应答）走堆叠卡不入审稿。
10. **UI 舞台**：右区正文+审稿**标签页切换**（随时切回正文互不打断）；审稿窄栏列审稿项+影响行；quiet 规格+基板 token，禁第二套「计划卡/审稿真相」。
11. **审稿状态持久化载体**（参谋部复核必补项）：审稿组（`ReviewBlock[]` 含 status 与块映射）落盘为**章节伴随状态文件**（与章节正文同目录的 `.review.json`，精确路径与命名施工时定），且**读写全走 `WorkspaceHistory` 管道**——registerWrite 进时间线/快照，决议记录=状态文件的历史快照链（基线 8 由管道免费满足，禁额外决议日志系统）。刷新/重进恢复=读状态文件重建 store（G1 `content_review` 件随之恢复）。accepted 块的正文写入与状态迁移须同轮落盘：状态文件记录已应用正文的 revision，启动对账检测半完成态（状态 accepted 但正文 hash 不符→该块转 void 并披露，禁静默重写）。
