## 0. 一句话目标

把 Agent 面板从"按能力清单组织的工程界面"重构成"跟主编聊天的作文流"，同时把落库审查、创世向导两件接到用户手上——链路不人肉驱动自跑。

**三条底线**（违反任何一条=返工）：
1. **骨架不动**：Agent 面板现有布局骨架不改，只做组件级升级（用户拍板，理由：改动面小、上游冲突小、可独立验收）。
2. **功能一件不丢**：现有顶栏/底部全部按钮先做收编去向表（哪个按钮去哪了），再动代码。v2 曾画丢功能按钮，不许重演。
3. **UI 与接线配套交付**：每一批交付的必须是"跑起来用户看得到"，不允许只做后端等下批接（旧 fork 败因：后端八件全做完、前端接线零件，项目死于此）。

## 2. 批次 1：Agent 面板骨架

### 2.1 作文流排版（总纲的落地）

参照 ZCode 实况（用户截图确认）：

- **用户消息**：右侧气泡，宽度上限约 55%，无头像无名字（hover 功能按钮在**右下**角）。
- **AI 消息**：近满宽、**零边框**——正文、思考、工具过程全部融为连续文档流，像一篇作文铺开。分隔靠留白与字色（text-secondary/muted），不靠框线。
- **AI 身份锚定**：左侧引出箭头锚定；功能按钮 hover **左下**角（不是右下）。多 agent 会话例外：轻量身份标记。
- **过程行**：灰色小字行（图标+一行摘要），可点击展开细节——"思考·持续了几秒˅""已工作 37 秒˅"同款。**Claude 官方印证：每个工具组上方给一行思考回顾（one-line recap above each tool group），采纳此形态。本条即旧图纸 #4「工作块折叠人化」的最终形态（图纸 44eeb913），按最终形态一次做，不做过渡版。**
- **批次 1 文件所有权（防 5.3/Flash 同文件冲突）**：AgentChatSurface / AgentChatFlow / AgentComposer / AgentTextBubble / AgentToolNode / AgentWorkBlock 等一切**既有文件**的改动（含样式）归 5.3 串行独占；Flash 只**新建文件**（缓存环/思考档下拉/刻度条/后续大纲面板等新组件）+ i18n 块尾追加。
- **交互件（需要用户点的东西：选择题/审批卡/待定项）仍为"轻量卡"**：可点对象必须有视觉边界——用浅底色或左侧一根细线，不用重框线。纯展示零框，需交互轻卡。

### 2.2 顶栏收编

现有七按钮（新建含 profile 下拉/附件/LinkedAgent/会话树/系统提示词/会话列表/关闭）：

- **删除"关闭"按钮**（用户拍板：面板常驻右栏，Activity Bar 已有开关，顶栏关闭冗余+误触恐慌）。
- 其余按钮做**收编去向表**：收进 ⌘K 命令面板 / 收进「+」菜单 / 保留顶栏，三类去向逐一登记（v2.1 已有收编去向表底稿，先核对补全再动）。
- **模型选择器**：右侧加**思考强度档位**（低/中/高，i18n）；左侧加**绿色环形缓存指示器**——**复用现有数据，零新后端**：AgentComposer.vue:703 起底部状态条已有 cumulativeCacheHitRateLabel / cumulativeCacheCompactLabel / cumulativeCostCompactLabel 等 props（智谱 API 返回 `usage.prompt_tokens_details.cached_tokens`），绿环=一眼概览态，hover=现有 cumulative 标签文本，点击=复用 gauge 芯片的 open-context-inspector 行为。
- **底部状态条整体保留**（作者原作，含 gauge 上下文芯片/累计输入输出/缓存命中/费用/连接状态/运行相位/模式徽标），只随作文流重排对齐。

### 2.3 会话树内嵌（刻度条）

- 面板内嵌刻度条（右侧细条），**高度固定、格数封顶约 50 格**：对话越长每格聚合越多消息（VSCode minimap 模式），**绝不缩到选不中**；可点击、可拖动定位。
- hover 显示该格覆盖范围的摘要（旧库"放大镜悬停预览"图纸：commit 0f92cc9a）。
- 覆盖式展开三形态：hover 小预览卡 → 点击中面板 → 「查看全部」完整会话树。
- 覆盖层尺寸口径：宽度=内容区 65-70%，高度≤面板高 70%（内部滚动），上下不出面板边界，点外部即收。
- 注：本条是会话**分支**导航；批次 3 旧图纸 #1 大纲面板是当前会话**内容**导航——两个东西都贴边，由 5.3 出统一「贴边刻度」交互规格（位置/颜色/hover 触发一致性），不许出现两套长相不同的边条。

## 3. 批次 2：交互件

### 3.1 AI 出选择题（定稿 1B：按钮组+其他自由输入）

- AI 提问时消息内直接带可点击选项按钮组（轻量卡形态）；**点选=自动作答发送**，不打字复述（用户曾被逼回"2,a"）。1B 变体：按钮组之外带「其他」自由输入框（逃生门——选项选不中时打字，不用复述问题）。
- **两级呈现**：主推 3 个（AI 按相关度精选）+「更多方向 ▾」可展开，**数量不设上限**（用户："有意思的可以多扩展，我灵感也多"）。
- **灵感库**：选择题未选项自动存入本书灵感库（lorebook 新节点类型，补上"未选方向去哪了"）；灵感库条目可回看、可重新发起讨论。规格包阶段先查 lorebook frontmatter `type` 枚举的 server 校验扩展点再定存储形态。
- **置信度标**：AI 回答带 ✓/？标记；**低置信自动降级为选择题**（硬规则）。
- **AI 侧协议规则**（改 skill 提示词，novel-guide 层）：提问题必须附选项，没选项的问题不许问；未定事项（Pending）主动变选择题递上来（"别藏着掖着"）——收拢弹药 19/38/29 三条。
- 消费话术包组 4（确认卡按钮文案："就这么定/改几处/推倒重来"）。

### 3.2 任务胶囊 + 进程卡

- **胶囊只收过程、不收结果**：writer/子 agent 运行时，胶囊=状态入口（"正在写第 3 章 · 已 2 分钟"），点开看思考流+工具过程（进程卡）；**干完的结果（正文/结论）照常进消息流**。
- 完成后胶囊收成轻量收尾行："已思考 45s · 已写 2200 字"，可展开回看过程。
- **铁规则：凡是需要用户做决定的（提问/审批/选择题）永远直接出现在消息流，绝不埋进胶囊**（弹药 38 教训：9 个未定事项卡死主链）。

### 3.3 思考流分级

- 探索级（计划批准前）：3-4 行思考摘要滚动流。
- 执行级（计划批准后）：安静执行——里程碑式播报，不刷屏。
- 完成自动折叠为"已思考 Ns"。切换点=计划获批。
- 开源参考（不造轮子）：Vercel AI SDK reasoning part / LobeChat / open-webui 的思考流组件形态。

### 3.4 支线流转（编辑器快捷对话重定位）

- 选区引用提问 → 自动新建**分支**（不污染主线）→ 答完「采纳回主线」或「留在分支」。回主线按钮只在支线里出现（**按钮跟状态走，不跟位置走**）。
- 主线/支线统一消息卡片规范（作文流规范两用）。
- 底部功能栏的支线唤醒入口保留接入。

## 5. 批次 4：落库审查流 + 创世向导

### 5.1 落库审查流（图 1 定稿六要素）

1. **1C 收件箱正门**：审批统一进收件箱。

## 6.5 分工总则（2026-09-20 配额优化定案：5.3 刀刃化，Flash 承担约 2/3 行数）

**原则：5.3 出规格与挂载点，Flash 照规格填，5.3 验收。规格越死，Flash 越准。**

| 归 5.3（前线） | 归 Flash（工程队/workflow 子代理） |
|---|---|
| AgentChatSurface / AgentChatFlow / AgentComposer 等巨石文件的**结构性**改动（拆挂载点/状态机手术） | 一切**新独立组件**（刻度条/缓存环/选择题卡/任务胶囊/大纲面板/向导板等） |
| 落库审查流安全链路（审批/execute_world 挂点） | 作文流**样式改造**（CSS/模板类，按已定规格） |
| 每批施工规格定死+验收把关+收编去向表核对 | **按旧库图纸重写**（批次 3 整批——旧 diff 就是规格） |
| Flash 连续两次修复失败的活接管 | i18n key 批量、文案填充（话术包 55 条）、词表替换（workflow 扇出） |
| — | **中复杂件 Flash+max 首攻**：会话树滚动联动、支线分支机制、巨石内样式接线——两次不过停手上交 5.3 |

**执行细则**：
1. 每批开工时，5.3 先交「规格包」=涉及文件清单+挂载点位置+组件 props/emit 契约+验收断言，Flash 按包施工；缺规格的件不许直接派 Flash。
2. Flash 施工用 worktree 分支（task-009c-f1/f2…按件分支），5.3 逐件验收合并——巨石文件冲突由 5.3 串行处理。
3. Flash 连续两次修不过同一问题 → 停手上交 5.3 接管（停手时写清已试方案，不许第三次的硬怼）。
4. 批量扇出活（词表/多屏核查/多文件 review）用 `/workflow` + `subagent_model=GLM-5.3-Flash`（积分约 1/9）。
5. i18n 冲突预防：双方只块尾追加自己的 key，提交标注 `[i18n-add]`。
6. **档位规则（思考 token 全额计费，高档=多烧思考，别乱开）**：执行型机械活（替换/填充/格式）=Flash$**low**；分析型（对照/审查/判读）=Flash$**high**；复杂施工（联动逻辑/机制类/巨石样式接线）=Flash$**max** 首攻（Flash 最高档仍远低于 5.3 价格）；5.3 自留件默认 $high、深任务 $max。
7. **旧库 diff 仅作行为规格**：旧库代码结构≠新库现状（上游已多轮重构）——学行为与接口设计，按新库现状重写，禁止照代码抄；组件挂载接口以新库为准。
8. **i18n 冻结窗口**：批次 5 词表批量替换（改既有值）执行期间冻结其他一切 i18n 改动（替换与追加混行必冲突），跑完合入再解冻。

## 7. 全局铁律（每批开工前重读一遍）

1. **i18n 铁则**：禁硬编码中文进组件；测试断言用 i18n 键。
2. **测试口径**：server/plugins 测试必须 vitest 跑（bun test 全挂：vi API+nitro 虚拟模块）。
3. **nitro 缓存坑**：改 server 代码后必须清 .nuxt/dev 或 grep bundle 验证（增量缓存会跑旧代码骗人）。
4. **user shadow 验收**：skill/协议层改动必须实际开会话验证行为真变了（文件 diff ≠ 运行时加载；发现 hash 不一致报差异勿静默覆盖）——78 号品读三层 seam 教训。
5. **停止条件**：每批完成判据=该批验收清单全绿；连续两次修复同一问题失败=停手，写清已试方案与现场，上报待新口令（78 号文化，不许硬怼）。
6. **偏差披露必填**：交付报告带偏差披露节——测了什么/怎么测的/没测什么/执行与任务书的偏离，缺一即打回（执行诚信四铁律）。
7. **收编去向表先行**：动任何按钮/面板前，先落"现状→去向"表进交付报告。
8. **旧库只读**：`D:\MyProject\neuro-book失败fork开发但可以学习经验\` 只许读（git show 学 diff），禁止 cherry-pick/改动/合并。
9. **worktree 流程**：task-009c 分支开工；commit 前验当前分支（多窗口曾撞分支）；验收合并完成前不删 worktree。
10. **上游冻结**：单C 五批施工期间**冻结上游 rebase/merge**（上游也在活跃改 AgentChatSurface，中途同步必撞巨石）；全部完工验收后再做一次同步。盯梢 Cron 通报照常但只记录不动手。
11. **基线与回滚点**：开工前跑全量测试记录基线数（vitest 口径）；每批对比基线防"改 A 坏 B 而不自知"；每批合入 master 打 tag（009c-batch-1 起），出问题按批回滚不整仓退。
12. **BOARD 登记**：每批开工在 BOARD 登记"009单C批次N"行，交付更新状态——聊天报告不算完成。

## 8. 验收

每批交付验收四层：
1. headless 截图（关键屏）+ vitest 相关面全绿 + typecheck 零错。
2. 前线文件审查（diff review + 收编去向表核对）。
3. 用户真机走查——参谋部出**「3 分钟验收清单」**（点哪几处、看什么、什么算过），不给长清单。headless 截图须用真实书籍的既有会话数据构造（空会话截不出消息流效果）。
4. **用户截图调 UI**：跑起来后用户直接截图发前线挑毛病（微调进当批或下批头部）。

用户侧最终标准（009 的初心）：从"我想写个点子"到落库审查完成，**全程不需要人肉驱动、不需要看 YAML、不需要打字复述选项**。
