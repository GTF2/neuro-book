# PRODUCT.md（仅服务 009 设计提案，从用户 brief 与走查证据推断）

> 本文件由 impeccable init 的 brief-only 路径产出：无访谈机制，全部事实来自 2026-09-20 用户线框图任务书与 `docs/tasks/evidence/走查-v1.html`（38 张实截）。假设均已标注。

## 产品

NeuroBook：本地优先的 AI 长篇小说创作 IDE（Nuxt/Vue，桌面浏览器使用）。本 fork 属主 GTF2 个人使用。

## 访客与本产出

- 本产出的访客是**用户本人**（编程小白，产品唯一用户），任务是审阅三张重构方向线框图、在变体间做选择并挑毛病——**这是一份决策文档，不是产品页面**。
- 模式：Read（读者理解方案并做决策；线框图自身去视觉化，信息结构优先）。

## 用户与使用场景

- 长篇网文作者，多章大项目（实测 236 章/190 万字项目在库）。
- 桌面浏览器（1920×1080），白天/夜间均有使用。
- 高频任务：写正文、让 Agent 改稿/落档案、审查 AI 写入、新建书。

## 硬约束（用户任务书原文具有合同效力）

1. 低保真黑白灰、零依赖单文件 HTML、每张 2-3 个可选变体。
2. 图必须基于现有界面改造：机制不能凭空造、不能删真实功能。
3. 每个区块必须能指认出处（现有软件元素或一条改造需求），末尾附一页对照表。
4. 三图主题：落库审查流正门 / Agent 面板全套 / 创世向导开场（详细规格见任务书原文，brief wins）。

## 假设（无访谈，从证据推断）

- 「黄金三章」= 网文行话，指向导完成后直接进入前三章的连贯写作流。
- 「落库」= AI 产出写入项目档案（lorebook/设定卡），对应现有文件变更审查机制。
- 用户希望文档自带轻量选择收集（每变体可选可批注、可汇总导出），推断自"给用户做选择题挑毛病"——若不需要可忽略，不影响阅读。
