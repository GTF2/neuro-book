# 单D 架构↔UI 对账报告（2026-09-22）

> 目的（用户令）：底层架构有没有完全展现到 UI 设计上、匹不匹配——防主界面"东西少了/多了出怪事"。
> 底账：UI 承诺清单 58 条（蓝图+原型）× 底层清单 53 功能+16 数据+15 AI 能力+14 半成品（主仓库+预研四件实读）。

## 一、总判断

**骨架匹配良好**：三栏翻转（IDE/Agent 双分支现成）、待办六类×审批流（46 工具+pending 三类草稿）、伏笔下钻（StoryPromise 全字段在）、驾驶舱数据源（伏笔数/待拍板数可查）、刻度/绿环/输入栏（真机已磨四轮）——设计没有凭空画骨架。

**三个必须处理的问题**（下详）：待办统一库不存在（架构级）、审稿态全新（已知最大施工量）、14 个底层功能无 UI 入口（待筛）。

## 二、架构级缺口（任务书必须显式列）

**G1 待办统一库不存在**。设计承诺"六类待办单一真源+落库持久化+重进恢复+三处计数同减"；底层现状=三处分散存储（agent-pending-resolution.ts 会话级草稿 / jobs pending / workflow PendingAsk），无统一待办库。
→ 施工方案二选一：①新建 unified-todo 聚合层（读三源+落库快照，推荐）②三源各自落库+聚合查询。**不解决这个，堆叠卡/驾驶舱/收件箱三处同源就是空话**（真机 Workflow 面板计数不一致 bug 的根因同款）。

**G2 审稿态零实现**（已知）：reviewMode 全仓无代码、块级 diff 状态机（pending/accepted/rejected/void）为新数据结构。文件历史库（nb-history）的 diff 能力可复用为对照视图底座。

**G3 正文块级 diff 数据结构**：融合审稿"通过块立即写入正文"需要块↔正文的映射结构，现无。建议挂在文件历史库快照上扩展。

## 四、UI 缺入口（底层有、设计没提——14 项待用户筛）

**A 类·建议补进设计（核心循环用得上）**：
1. **文件版本时间线+误删找回**（nb-history 场景 1-2 全套验收过）——挂历史对话二级页 or 文件详情
2. **Jobs 后台任务面板**（列表/取消）——设计被"驾驶舱 AI 在干啥"部分覆盖，完整面板待定去留
3. **Passport 账户/备份/恢复码**——设置页设计漏了账户分区

**B 类·待用户拍板去留**：

5. NovelPromptBar（IDE 模式稿面底部 inline 输入栏）——布局翻转后与 Agent Composer 疑似冗余
6. Monaco 源码模式（rich/source 双模式）——单D 设计只画了衬线阅读态
7. Trace 查看器（LLM 调试）——建议藏开发者菜单

**C 类·范围外/保持现状**：
