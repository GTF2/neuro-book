# 单D · UI 总攻蓝图（v1 草案，待用户拍板）

> 2026-09-22 参谋部编制。来源=009 收集册 291 条+旧库 DESIGN.md/SIMPLIFICATION.md/prior-art 全文补读+写作流程与 AI 监制模式调研（Novelcrafter/Sudowrite/卓伊凡方法论）+用户全程共创决议。
> 定位：批次 1 之后所有 UI 工作的总纲。执行模式=先看图后施工，用户只做"看图选择"。

## 一、为什么改打法

批次 1 走了四轮返修，磨的全是视觉形态（宽度/间距/对齐/颜色）。根因：**视觉判断只能发生在"看到成品"之后**，而旧流程把它推到施工后的走查环节——返修是必然的。

**新原则：先看到满意的样子，再施工。** 用户在选择题模式下产出质量最高（已验证，见打法档案），本蓝图全部决策点都按"看图选择"设计。

## 二、新流程（五步，每步零代码）

1. **蓝图定稿**（本文件）——需求还原，用户答三道题定稿。
2. **三议题选择题卷**——界面主角 / AI 位置 / 布局比例。参谋部备参照物截图，用户指认。
3. **设计底座样张页**——候选气质各一页样张（色板+字体+组件+界面拼样），选一页=定整套设计宪法（design token）。之后所有界面从这套取值，无自由发挥空间。
4. **全量交互原型**——HTML 网页原型（非死图片）：
   - 编号标注：每个元素挂①②③徽标，悬浮显中文名，跨图编号稳定，一键开关（提意见开/看观感关）；
   - 场景切换器：旁挂调试栏，所有状态一键直达（正常/空/加载/错误/极端五态全覆盖；审批单/工具失败/选择题/workflow 应答等真机难复现状态尤其要全）；
   - 深度可达：一至四级界面全部真实可点（弹层/下拉/悬停可演示）；
   - 两批交付：先主流程全景，后稀有状态；
   - 原型进仓库，git 管版本，翻旧账可追溯。
5. **照图施工+机器对图验收**——playwright 截图对比（原型 vs 真机）自动比对差异，人只看机器判"不一样"的处。

**配套规矩**：候选滚动生成（全否决=喂料，换参照物再来，无限续）；杂交选择（A 的颜色+B 的布局+旧库的刻度条，整选不出就拆维度拼）；兜底（用户最顺眼的日常软件当底只换皮）；口令自包含（截图指代必须转译成代码定位再下单）。

## 三、产品蓝图

### 第 0 层 · 本质需求

**一句话：你说点子，AI 写书，你当主编——一个字不用写也能出书。**

1. **长而不崩**：几十万字人物不崩、设定不忘、伏笔要还；约束只守底层宪法，新人物新事件自由引入（用户创意扩展性原则）。
2. **好而不假**：去 AI 味、文风节奏可控。
3. **小白能玩**：不懂技术不懂写作，开口说话就行。

### 第 1 层 · 核心循环（监制的一天）

**定方向 → AI 生成 → 审稿 → 拍板入库 → 下一章**，循环往复。

两个贯穿：
- **指挥通道**：跟 AI 说话（出点子/做选择/下指令），右栏常驻。
- **流程驾驶舱**：一眼看到写到第几章、N 个待拍板、哪些伏笔没还（新推导，源于实测"9 个未定事项写进文件后无人理"卡点）。

**验收线（旧库 DESIGN.md 五条 Journey 量化）**：J1 首字 90 秒 / J2 AI 首章 10 分钟 / J3 续写 20 秒 / J4 伏笔闭环 60 秒 / J5 扫 AI 味 2 点击。界面好不好跑这五条算账。

### 第 3 层 · 界面分区（2026-09-22 用户翻转定稿）

**功能导航+驾驶舱（左）→ AI 面板（主舞台，居中偏宽）→ 稿面（右，多功能舞台）**

翻转理由（用户推理链）：监制定位不写字，稿面常态闲置，AI 对话是主交互面。三方背书：用户身份实证（实测全程在对话区活动）+星炉 42% 商业验证+旧库"AI 一等公民"判词。Novelcrafter/Sudowrite 稿面居中不适用（其用户自己动笔）。

配套机制——**主次跟阶段走**（同"按钮跟状态走"哲学）：
- 常态：AI 面板为主；稿面空白态显示"AI 正在写第 N 章/最新产出预览"，非白墙；
- 审稿态：点"审这章"→稿面（对照视图）扩张接管、AI 收窄，审完一键回常态；
- 不做手动分栏拖拽（小白不需要学）。

**二级内容展示分层（2026-09-22 定，主界面骨架的一部分；二级界面细节后批做）**：轻内容（历史对话/收件箱/待拍板队列）=左栏面板展开；重内容（剧情大纲/角色档案/世界书/世界引擎/**设置**）=中间工作区打开（与审稿态同机制，"工作区态"）；**弹窗仅用于破坏性确认（删除类）**。设置=工作区页的 VS Code 式形态（左分区导航+右内容+即时生效无保存按钮，非模态——NN/g 模态打断结论+VS Code/主流 SaaS 内嵌页先例，用户"被打扰/被控制感"关切 2026-09-22 提出）。主界面状态位三个：常态/审稿态/工作区态。

**待办统一体系（2026-09-22 用户版 1 走查共创，体系级决议）**：
- **发现入口唯一=驾驶舱**：待拍板/伏笔未还/Workflow 待应答全部是驾驶舱的行（每行明确按钮化——hover 灰底+可按容器，符合组件宪法 2；禁"不像按钮的按钮"）；原"详情卡区"（版 1 编号 8）取消，其内容并入驾驶舱（同一功能区不拆两张卡）；驾驶舱"展开收起"按钮取消，详情常显，快速处理以横条功能块嵌在驾驶舱内。
- **处理舞台唯一=AI 面板输入框上方的内联堆叠卡**：点驾驶舱行→该类待办**全部弹出**为堆叠卡（书/本堆叠视觉），**右划=通过→划掉消失→下一张浮上来；左划=拒绝→下一张浮上来**（滑动决策动效）；非模态、不居中弹窗。
- **Workflow 待应答并入本体系**：只在驾驶舱占一行提示（不再有独立徽标+弹窗）；处理走同一堆叠卡（位置=输入框上方）。
- 聊天流内审批卡保留为"就地快批"入口（出现时就地批），数量自适应路由升级：1-2 条聊天流快批 / 3+ 条引导进堆叠模式。
- **待办分类账（2026-09-22 R3 四轮走查真机实战后补定）**：四类待办=①工具审批（Agent 请求执行写库/改文件等动作的批准/拒绝）②设定拍板 ③伏笔未还 ④Workflow 后台任务应答。现状病灶（用户《新小说1》拆书实测）：工具审批被塞进批次 1 过渡形态的"流程等应答"面板与 Workflow 应答混类，且徽标计数（0 个）与面板内队列（待处理 1/3）两处数据源不一致——单D 施工时四类全按本体系收编（驾驶舱发现+堆叠卡处理），"流程等应答"独立面板届时取消。

**输入栏规格（同轮走查决议）**：输入框随字数自动增高（去手动"放大"斜杠按钮）；图片附件在输入框内、文字上方悬浮、不出框；上下文/统计信息整合进绿环（hover 全量），不在旁边重复摆放；**输入栏钉死面板底部固定**，不随消息收放浮动。

**版 1 其他走查意见处置**：稿面预览卡 UI 叠挤=原型瑕疵（真实稿面不堆 UI，注意项）；长会话刻度场景补画（按 009C1R2 真机形态，右缘宽度微调）；工作块子行缩进=009C1R3 件 2 已覆盖。

**布局终选+融合审稿大决议（2026-09-22 晚用户六版走查回传）**：
- **终选=版 3（纯指挥模式）为基底改造**，不是原样过审。改造清单：①堆叠卡视角修正（版 3 现状"从下看"透视怪，照版 2 的 20 号：当前卡全显+后两张露纸缘+右划通过左划拒绝）②输入栏照版 2 的 13 号（钉底/随字增高/发送钮全页唯一实底）③刻度只画在 Agent 面板（版 3 原型误画到稿面=bug，稿面永不刻度）④过程行 hover 说明在下方不出右侧⑤稿面收起态边条美化⑥**专注按钮裁撤**（与稿面开关重复；用户裁定常态与指挥模式本是一个东西=只差右栏宽度，两态合并）
- **右侧目录抽屉（新功能，用户提出）**：稿面右缘可点出浮动目录面板，读小说式列出全部章节，点击跳转——"咱们真正创作出来的每一章"。
- **融合稿面审稿界面（本轮最大原创决议，用户提出）**：右区=正文视图+审稿视图**标签页切换**；正常显示当前章正文，审稿项分块列在正文左侧，点审稿项→右区切到审稿视图（diff 对照+逐块通过/拒绝），标签页随时切回正文——审稿与看/改正文互不打断。**待办路由二分**由此确立：轻量快批件（工具审批/设定拍板/Workflow 应答）=Agent 输入框上方堆叠卡；正文重审件=右区融合审稿界面。原"稿件/待拍板"独立按钮取消，主界面全覆盖。
- **驾驶舱=纯引导按钮列（用户强化）**：所有行可点+右缘小箭头，点行唤起对应处理场（堆叠卡/融合审稿/伏笔清单下钻）；内容可扩（快速功能都可进）。
- **拒绝闭环（用户原创，补流程断头路）**：拒绝不能是死路——拒绝后该件变**引用气泡挂在输入框上方**，用户在输入框写修改意见、带着引用发送给 AI，AI 知道哪里被拒+为什么，改完重新提案。适用于堆叠卡与融合审稿两处。
- **待办持久化（用户工程关切）**：待办全部落库不存内存——Agent 中断/关界面重进后待办必须还在，驾驶舱=重新唤起入口。写入施工任务书验收断言。
- **待办分类×展现矩阵 v1（参谋部梳理待用户判）**：①工具审批（写库/改文件动作）→堆叠卡两按钮+拒绝闭环；②设定拍板（提案入库，带影响行）→轻的走堆叠卡，涉正文联动走融合审稿；③伏笔未还（提醒非审批）→驾驶舱下钻清单视图+标记计划回收章；④Workflow 应答→堆叠卡或聊天流就地快批；⑤正文变更审（改段落/换章纲等实质修改）→融合审稿界面（diff+逐块决策）；⑥计划确认（AI 列计划征求同意，两按钮装不下）→计划卡形态（分步列表+逐步可调+文字反馈），呈现位置待定稿。**路由判断权（2026-09-22 复核补定）**：跨类待办（如设定拍板）由 AI 提案时自带路由建议（轻/重+一句话理由），用户可手动改道——不由 AI 定死，也不全靠用户手选。**审稿视图准入=仅涉正文实质改动件**（用户定：不涉正文改动的进审稿=与堆叠卡重复）。
- **断头路排查（2026-09-22 复核补排，用户"头有尾"关切）**：出图 workflow 加一路排查员——六类待办+核心循环（定方向→AI 生成→审稿→拍板入库→下一章）每条路走"发起→处理→反馈→归档"全程，专找有头没尾的断点（如拒绝无反馈、应答无归档、中断无恢复），产出断点清单进蓝图后再出图。
- **图片附件规格更新**：多图=小方块网格、单图=小方块，hover 预览，禁一长溜横条（版 2 原型此处不抄）。

（原"稿面是全屏唯一浮起的面"条随本翻转修订为"主舞台是阶段函数"；首屏重心挪能力演示保留。）

**与"骨架不动"决议的边界**：本翻转=栏位顺序与宽度重排（AI 面板与稿面换位），全部复用现有面板组件，不建拖拽停靠等多窗口基建——属"能改能调整"，不违反"不可能从头来"。
