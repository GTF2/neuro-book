1这个功能做什么

  • 一句话：输入框右下角、发送键左边，加一个跟发送键同款的小按钮，图标是一颗星星。点一下，把你随手写的一句话补全成「对象清楚、动作清楚、产出清楚」的指令，直接替换回输入框，你再决定发不发。
  • 按钮本身就是状态（三态）：星星 = 可以增强；转圈 = 正在增强（此时不可点）；返回箭头 = 已增强，点它就是还原成原文。没有额外的状态条、文字和弹窗。
  • 不做的事：不替你想剧情、不新增任务、不改你的语气；只补全你没说全的部分（哪一卷、什么顺序、按什么依据、要什么产出）。
  • 空的输入框：按钮置灰不可点（没有内容就没有增强对象）。
  • 能看出改了什么：增强补上的部分在输入框里用浅紫底色标出，不用逐字对比。

2增强时具体补什么（写作场景的四要素）

你写的（原型里的示例） 增强后
继续,场景、章节简报如果能提前的话,提到前面 继续当前的拆书任务。如果场景简报、章节简报可以提前产出，请把它们的顺序提到前面——先给场景与章节简报，再继续正文拆解。
  • 对象：把「继续」落到具体任务上（当前拆书任务）。
  • 动作：把「提到前面」说成「先给 A、再给 B」的明确顺序。
  • 约束：只用你原话里已经出现的信息（「如果能提前」保留成条件句），不替你加「必须」「一定要」。
  • 产出：说清要的是简报而不是正文。

3技术怎么做（好消息：不用新造轮子）

  • 已有现成样板：项目里的「AI 解释这步」就是同一个套路——单独调一次模型、不建会话、不写对话历史（`tool-explanation.ts` + 对应接口）。增强提示词照抄这条路即可，不会污染你的对话，也不会让 Agent 因为增强文本而改变行为。
  • 需要新增：一个纯逻辑模块（提示词模板 + 调用）、一个接口（prompt-enhance）、输入框上的一个按钮，加上中英文文案。
  • 为什么不走「新建一个 Agent」：那会多出一条会话、多花一份上下文，而我们只要一段文本，属于杀鸡用牛刀。

4一条必须守住的边界（项目写作宪法）

  • 项目有份「写作宪法」，其中一条明确禁止把「意义类指令」喂进写手的动笔前上下文（不然会变成「人逐句指挥 AI 写正文」）。
  • 所以这个功能的增强结果只回到你的输入框——它是你说给 Agent 的话，怎么用由 Agent 决定；功能本身不会绕过流程往写手上下文里塞东西。
  • 这一条我会在正式的设计文档里写成「与宪法条款的对照答复」，改代码前先过这道关。
