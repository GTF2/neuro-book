1这个设计解决什么

  • 看得见：队列条直接回答两个问题——「谁发的」（你 / 后台任务 / 系统）和「为什么没送达」（暂停原因用人话说）。现在这两行只显示 <system-reminder> agent #26 返回… 这种机器原文，你看不出它是什么、为什么在这。
  • 能操作：每条都有「立即送达」和「忽略」；暂停时还可以「全部送达 / 全部忽略」，不用再靠「先发一条消息、再按 Ctrl+Enter」这种绕路。
  • 能自愈：队列暂停后，会话空闲时会自动重试（最多 3 次，间隔逐渐拉长）；还不行就明说「需要手动处理」并给你一个重试按钮。现在一旦暂停，只有你主动发「排队」消息才会恢复。
  • 默认折叠，不占地：平时只占一行——琥珀条说明「暂停了、几条没送达」，批量操作全在折叠条右上角（全部忽略 / 全部送达 / 详情），不展开也能处理；条目的单个操作也都排在各自那一行的右上角。
  • 展开也不顶屏：展开的窗口限高约 240px、内容在其中滚动（切「大量积压」情景可看到效果），底部把手可拖动调整高度、双击恢复默认。

3后端要配合什么（大白话）

  • 补一个「来源」字段：服务端每条排队消息其实都记着来源（你 / 子任务 / 系统），但发给界面时被去掉了。补上它，界面才能显示「后台任务 #26」而不是一串 JSON。
  • 补三个接口：「送达单条」「忽略单条」「解除暂停」。现在只有一个「停止时清空队列」的开关，所以界面完全没有办法处理卡住的条目。
  • 投递正文改成结构化：后台任务完成的通知，现在是 {"status":"completed"} 这种机器格式，建议生成时直接写成「后台任务 #26 已完成 · 任务标题」，界面不用猜。
  • 自愈逻辑放进队列本身：暂停后空闲时自动重试（3 次、退避），失败超限才等人工。目前没有超时和重试。
